# 验证、续作与交付

## 两条独立验收线

- 行为：对合同清单逐项做同输入/同前置条件结果对照，保留状态变化与失败恢复证据。可做自动差分的先自动；网络/第三方条件不同明确说明。比较可见文本与格式化结果，内部 key 改名不应造成漏文案。
- 视觉：按新的视觉规范及参考元素检查全部自有页面/组件/状态，而不是像素复刻旧 UI。正常字号真机录屏/截图标明页面、触发步骤、构建与未覆盖状态。检查导航/安全区/键盘/全屏遮罩/图标方向/动画帧率。

验证层次分别记录：静态/单元 → Debug/Release 构建 → 签名/安装 → 真机交互 → 真实接口与产物 → 发布包。缺运行环境继续不依赖设备的工作，明确未测；编译通过不得升级成验收完成。

对生成、转换、导出功能验证文件可读/可解码、格式、内容、时长/尺寸及目标去向，不只检查成功提示。对请求记录环境、HTTP 与业务码分别判断；HTTP 200 不代表业务成功。登录/支付/归因/订阅分别核对 SDK 初始化、配置来源和回调，真实付款/上传个人资料必须单独有相应授权。

Debug 测试和 Release 正式环境需明确，不能因为测试域名能请求就断言正式包可用；先检查环境/身份差异，再归因混淆。外部参数未经服务端确认不擅自重命名或“修复”。SDK/证书缺失保留连接点，禁止提交密码、密钥、证书、账号真实信息到公共 Git。

## 完成标准

每个自有功能映射到新实现与验收证据。仍转调原实现、占位图、未覆盖页面/异常状态、配置阻塞、未运行的设备测试都进入剩余清单，不计为完成。检查旧品牌/旧内部命名残留时逐项判断例外，不批量替换协议字段或许可文字。

续作读取准确基线和最近结果；同一未完成任务继续，不因换线程重置进度或重建工程。新变更影响旧通过项时重测。设备被其他项目占用时协调，不强占或卸载用户应用。

交付记录源码提交/脏状态、构建参数、产物 hash、设备与执行结果。APP/HAP 按平台正式工具验证整体签名，不仅凭内部包观察下结论。Git 按已授权目标上传；排除本地 `.migration-workspace`、测试私人数据、签名与构建缓存，保留需要审核的非敏感合同/例外摘要。上传与合并分别核实远端状态，不覆盖其他分支或升级现有项目。
