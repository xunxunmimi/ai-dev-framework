# 行为合同与重实现边界

## 盘点不是页面列表

逐功能记录：入口、前置条件、角色/会员状态、输入、校验、成功结果、失败/取消/中断/重试、导航返回、持久化、并发/生命周期、关联服务与验收证据。包含二三级页面、隐藏入口、权限拒绝、键盘、空状态、加载、禁用、离线、超时、重复操作、重启恢复。不能仅凭截图推断业务。

文案建立逐 locale/key/出现位置的基线：标题、按钮、错误、Toast、协议、订阅提示、动态格式、占位符、复数、标点与换行。内部资源 key 可变，最终显示字符串及格式参数语义不变。服务端动态文案保存测试条件/响应标识，不把个人响应或账号资料写进公共报告。Logo 是新视觉输入，不自动授权修改应用名或任何文字；新名称/身份配置有冲突时单独确认例外。

紧凑清单可用以下字段（用项目获准的本地工作目录保存，不默认提交）：

| feature/state | source evidence | expected input/output | copy keys/locales | new module | UI states | verification | remaining |
|---|---|---|---|---|---|---|---|

小状态合并记录，大流程按可独立验收切片拆分。不能把未发现功能当成无功能，不能为满足覆盖率省略空行。

## 独立实现，不破坏互操作性

先写行为合同再设计新架构/算法组合/状态机/数据流。自有类、文件、属性、方法与内部资源需符合新结构，注释根据新语义重写。代码顺序由职责组织，不为差异而随机打乱。不要复制原实现后仅改变量名；也不要为了不同而牺牲可读性或引入无意义逻辑。相似度/残留扫描仅用于查线索，不能证明独立重写，更不是规避审核承诺。

以下默认不能任意改，逐项列明原标识、使用方、保留原因及验证方式；不要为了“全部不同”破坏合同：
- 系统生命周期、平台强制名称、公开 API、SDK 调用、ABI/JNI、第三方代码及许可/版权声明。
- 服务 URL/路径、JSON 字段、枚举值、签名/加密协议、订单参数、回调和深链路。
- 用户数据结构、数据库迁移、文件格式、缓存语义与兼容键（需要改时写迁移并验证）。
- 系统或依赖要求的资源/清单名称，服务端提供的文字；应用身份只按新项目获准配置变更。

明确区分自有代码、共享公共库、第三方引擎、生成代码。共享库可作为依赖复用，但不得声称已独立重写。若目标要求重写共享自有模块，需纳入范围与工期，不静默排除。

## 历史案例的适用边界

风云格式工厂历史流程可参考身份配置、视觉替换、环境分离和包体检验经验，但其大量业务实现来自原工程改名/重排；不能把它作为“全量独立重写已验证”的样板。代码重命名不等于编译混淆；资源改名不等于加密；源代码已修改不等于 Git 已同步；产物已安装不等于业务联调成功。
