# 鸿蒙马甲包：保留原实现，重做视觉

所有显式选择本能力的鸿蒙马甲项目使用同一规则：新建自有类并在新类中重新编写代码，更新自有类名、方法名、变量名、常量名及方法声明组织，保留原功能、业务逻辑、算法和底层实现；按 Logo 和 UI 参考重做全部自有页面与图标，保留用户可见文案。不以换名或重做 UI 为由重写业务、替换引擎或改变导出内容；不用于规避审核，不承诺上架。

## 启用与范围

制作与验收期间仅使用本马甲包 Skill，不以前置安装日常框架为依赖。新目标通过 `installers/bootstrap_harmonyos_restyle.py` 先预检再显式安装；已有日常框架或其他控制上下文则停止安装，保留原状态并单独审阅交接，不覆盖、不卸载。完成验收后，才按用户明确决定接入 HarmonyOS 日常框架；仅当用户明确要求本次鸿蒙马甲制作，且本项目 `.agents/skills/harmonyos-app-reimplementation/selection.json` 的 `enabled` 为 true、`projectRoot` 与当前规范路径一致时使用。从 selection 读取 sourceRoot 后，重新验证源/目标读取策略；选择记录不授予业务读取、编辑、上传或收费服务权限。仅有源码目录或复制来的其他项目选择记录不算启用。用户暂停/撤销后停止，普通 Bug 不扩展为马甲制作。保留原能力 ID 和安装路径；旧 selection 的 intent 只记历史，不授权重写原实现。现有项目不自动替换、升级或改写任务记录。

首次独立安装见框架 `docs/鸿蒙马甲包独立安装.md`；旧安装文档中的日常框架前置不适用于此独立入口。源码/目标须分开且互不包含，源只读。已有目标修改先保留并核对；不覆盖并发工作，不复制源 `.git`、凭据或整个控制目录。先记录源 commit/dirty 状态与目标基线，不擅自提交用户修改。

输入：源项目、目标项目、授权范围、Logo、几张 UI 参考图、平台/API/设备约束、原实现依赖、受保护的输出布局、明确批准的差异与新项目配置。配置缺失可以留显式占位，禁止借用原应用生产身份冒充联调通过。缺少图片先做行为盘点，不能声称已完成视觉设计。从源调用链先列齐一个完整切片涉及的现有目标文件、新文件及可在隔离环境完成的检查，有缺权时将同一目的的精确范围一次合并确认。已有授权内的普通改写、新建和验证不重复请示；平台如另行要求授权，按实际受影响范围处理，其他独立工作继续。

## 执行顺序与交付

1. **先提取合同再编码。** 阅读 [行为与重实现](references/behavior-contract.md)，建立可追溯功能/页面/状态、文案、多语言、数据与外部合同清单。以源码、产品需求和实际运行交叉核对；未知项标记 unknown，不猜实现。
2. **从参考图生成新视觉系统。** 阅读 [视觉设计](references/visual-direction.md)，查看真实图片像素，优先提取颜色值、色板与语义色；布局可借鉴，但默认不逐样照搬参考设计。项目明确要求的设计约束另行遵守，受保护的内部布局保持原样。形成 token、组件与代表页，再覆盖全部自有页面、弹窗和状态。文案不改；系统/SDK UI 单独列例外。
3. **保留实现，分片换名与接线。** 对本项目实有功能建立源实现、目标新类与新方法、依赖、界面及验收映射。包括水印、合成、导出等自有模块；在新类中按原算法、处理顺序和依赖重新表达原逻辑，不重新设计业务状态机或底层链路。自有符号用有意义的新命名；按职责调整方法声明顺序，不改运行时顺序、常量值、平台强制和兼容标识，例外按边界文件记录。按已批准范围分片推进，保留可追溯变更、检查与剩余项；不越读写范围，不认领或修改其他任务。独立 Skill 安装不是安装日常任务运行器，也不生成任务协议状态或验证通过证据。
4. **逐片验证并恢复推进。** 阅读 [验证与交付](references/verification.md)。行为等价与视觉新设计是两条独立验收线；验证实际文件/返回值/状态，不只看 Toast。完成一片记录结果并继续下一未完成项；受阻只暂停受影响项。恢复时读当前合同、代码变更和未完成清单，不把历史“已完成”当最新事实。
5. **报告事实。** 已实现、已静态检查、已构建、已真机验证、未测、配置阻塞分别列出；没有真实证据不宣称全量完成。上传、合并、发布按当前明确授权执行；本能力的安装不自动授权这些操作。

不自动安装图片生成、浏览器或商业服务依赖。可用且获准的绘图/生成工具用于新资产；不可用则先实现授权范围内的原生/矢量资源并明确差距，不把占位图当最终切图。参考和产物保留授权来源。
