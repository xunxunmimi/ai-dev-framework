# iOS 代码质量补充

仅在 D2/D3 源码改动、D4 中相关高风险路径，或用户明确要求代码质量/架构/注释审查时读取。先应用共享代码质量契约，再应用以下 iOS 约束。

- 沿用项目已有 MVC、MVVM、Coordinator 或其他边界，不为单次功能并列创建第二套架构。View/ViewController/ViewModel、领域服务和数据访问各自只承担项目中已经约定的职责。
- UIKit 与 SwiftUI 保持单一状态来源；导航、弹层、异步结果和生命周期恢复不能由多个对象重复持有互相覆盖的状态。
- Swift 的 actor 隔离、`Sendable`、任务取消和错误传播写在真实并发边界；Objective-C 的 ownership、Nullability、delegate/block 生命周期和线程要求在类型或契约上明确表达。
- 闭包、通知、KVO、delegate 和异步任务检查释放与解绑路径；不要用注释掩盖循环引用或生命周期不清。
- 每个本次新增/改动的自有 Swift/Objective-C 函数/方法写中文用途说明及适用契约；实现注释重点说明业务不变量、系统版本差异和恢复策略。
- 新协议、基类、泛型层或依赖注入入口必须有至少一个真实替换点、测试边界或平台边界；否则优先使用直接实现。

最终自检只报告会影响理解、修改安全或实际扩展的事项；纯个人风格差异不阻塞完成。

## 本次中文注释检查

每个自有函数/方法说明用途与适用的参数、返回值、异常、异步及副作用；成员、属性和常量说明用途、单位与状态。重要局部变量/计算步骤与兼容分支解释意图、原因和边界。改动同步注释，排除生成代码/第三方。人工核对是否符合实际行为；静态规则不能证明语义准确，不按注释行数验收。
