# iOS 日常开发规则

适用于普通 Objective-C、Swift、UIKit 和 SwiftUI 项目。它把任务按 D0-D4 分级，让小修改只做最小充分检查，大功能和高风险改动再逐步扩大验证。

它不是迁移框架，也不会安装第三方 Skill。迁移项目应使用 `ios-to-harmony-migrator-v2`。

## 安装到项目

```bash
./setup-project.sh "/你的/iOS项目绝对路径" ios-maintenance
```

脚本会：

- 检查项目是否具有 iOS/macOS 工程特征；
- 创建项目内 `.codex-rules/ios/`；
- 创建 `.ai-project/lifecycle.json`，并复制共享的轻量任务路由器；
- 生成项目能力候选缓存与框架安装清单，供 D2+ 定向验证和后续安全升级；
- 在根 `AGENTS.md` 中加入一条短入口，不覆盖已有规则；
- 保留用户自行修改过的规则文件；
- 遇到迁移项目时停止，避免和迁移框架重叠。

安装后可编辑项目内 `.codex-rules/ios/PROJECT.md`，填写实际架构、Scheme、构建和测试命令。另一台电脑只需复制整个规则文件夹，再运行同一命令。

能力缓存不授权执行未确认命令。框架升级使用套件根目录的 `installers/audit-project.sh` 与 `installers/update-project.sh`；受管文件存在本地修改时更新会停止。

## 使用

直接描述任务即可，例如：

```text
修复保存后页面不刷新的问题，按项目日常开发规则选择最小充分验证。
```

```text
开发新的订阅管理功能。先判断任务等级；给出可审查方案后分阶段实现和验证。
```

只有任务真正涉及对应领域时，才使用已安装的 `swift-concurrency`、`swift-testing` 或 `ios-simulator`。

可选的蓝湖 MCP 和 `ponytail-review` 也由 D0-D4 自动路由：蓝湖只在存在设计源且任务需要视觉证据时按范围读取；`ponytail-review` 只在 D2/D3 最终 Diff 出现复杂度信号时最多运行一次。规则包不会自行安装工具，工具不可用时继续按项目现有证据工作。

任务等级由 Codex 自动判断，不需要用户每次声明。D0/D1 默认不启动模拟器、不写新测试、不截图、不生成独立报告，App 运行验收交给用户；发现导航、数据、权限、共享状态或跨模块影响时自动升级。

代码质量同样按等级加载：D0/D1 只在最终 Diff 内检查命名、职责和必要注释；D2 只检查受影响文件；D3 才增加模块边界、公共接口和扩展性审查。注释解释原因、约束和生命周期，不追求逐行注释，也不会因此自动运行模拟器或生成报告。

明确的小问题不运行分类脚本；范围不清、D2+ 或脏工作区才用脚本保存任务基线。分类只看本任务 Diff，不会因为项目里别人的未提交改动扩大验证。
