# iOS 日常开发工作流

适用于普通 Objective-C、Swift、UIKit 和 SwiftUI 开发。迁移项目、高风险发布流程和用户当前明确要求拥有更高优先级。

## 先定范围

先查看 Git 状态，保留已有修改。根据当前请求和实际影响选择等级；不因项目很大而自动提高等级。

先读 `.ai-project/lifecycle.json` 和当前平台 `PROJECT.md`。明确的 D0/D1 在内存中判断，不运行分类器、不写任务报告。范围不清、D2+、交接或工作区已有大量修改时，才使用 `.codex-rules/_shared/task_router.py` 保存任务基线并生成 `.ai-project/tasks/<task-id>/context.json`。分级采用 `pre → post → final`，检查调用链后可以升降级；最终只计算本任务文件，旧脏改动必须排除。

- **D0**：文档、注释、无行为变化的元数据。只做格式或语法检查；构建仅在配置可能影响编译时运行。
- **D1**：局部、可回退、影响明确的小 Bug。读取相关文件和直接调用链，做最小修复；默认把 App 运行验收交给用户。
- **D2**：一个页面、组件或普通功能，或涉及导航、持久化、异步状态和恢复的行为修改。检查相关状态，构建相关 Scheme，并按风险运行相关测试或冒烟流程。
- **D3**：跨模块、大功能、公共接口、数据模型或新依赖。先形成可审查方案，再分切片实现；验证受影响模块及关键集成路径。
- **D4**：账号、支付、隐私数据、数据迁移、删除、签名或发布。记录风险和缺失证据，执行项目规定的完整验证；需要外部授权的操作停在授权前。

Codex 根据请求、改动范围和代码事实自行分级，用户无需声明大小。用户指定验证方式时遵从用户要求。不确定时从较小等级开始；只有依赖扩散、失败或不确定性得到证据支持时升级。修改行数少不一定是 D1；公共接口、数据、导航、权限或安全边界变化按实际风险升级。

## D0/D1 快速通道

- 默认不启动模拟器、不运行 UI 自动化、不截图、不录屏、不新增测试、不生成独立验收报告。
- 检查最终 Diff 和明显的语法、类型、资源引用问题。只有改动存在实际编译风险且有便宜的定向命令时才构建受影响 Target。
- 不为了证明流程完整而调用 `ios-simulator`、`swift-testing` 或通用审查 Skill。
- 最终只简要说明改动、已做的最小检查，并标记“App 运行验收由用户完成”。
- 如果检查发现影响导航、共享状态、持久化、权限、并发边界或多个模块，自动升级到 D2/D3。
- 不读取历史报告、原始日志或无关模块；需要时只读取证据索引和指向的局部内容。

## 外部能力自动路由

等级只控制调用上限；任务类型、项目配置和证据缺口共同决定是否调用。外部能力不可用不得阻塞普通开发，也不得在任务中自动安装。

### 蓝湖 MCP

- D0 默认关闭；只有用户明确要求从蓝湖整理需求时按指定文档读取。
- D1 仅限颜色、字体、间距、圆角、图标、切图等局部视觉问题，并且本次提供蓝湖链接或 `PROJECT.md` 已配置设计源；最多读取一个目标区域。
- D2 的新页面、组件和视觉还原在设计源相关时读取目标页面总览、必要区域及素材。D3 只扩展到当前功能切片，不扫描整个蓝湖项目。
- D4 默认复用已有设计证据；只有发布阻塞明确来自视觉证据缺失时才读取。普通逻辑、编译、数据、导航、并发和状态问题不调用。
- 默认只读，禁止自动发布、编辑、删除留言或发送通知。设计事实优先级按 `PROJECT.md` 执行；未配置时以当前 App 行为和用户本次指令为准。

### Ponytail Review

- D0/D1 不自动调用。D2/D3 在实现和必要验证完成后，只有最终 Diff 出现一个强信号或两个普通信号时调用 `$ponytail-review` 一次；D4 默认不调用，除非用户明确要求。
- 强信号：新增依赖、单实现协议/工厂、重复实现系统能力、为局部功能新增完整中间层。
- 普通信号：多个无必要包装层、未使用扩展点、重复帮助函数、实现范围明显超出请求。
- 它只审查复杂度，不替代正确性、安全、性能和发布验证；不得删除必要兼容代码、错误处理或可访问性支持。只采纳可证明不改变行为的建议，修改后重跑最小相关检查，不循环审查。

## 实施边界

- 先读取 `PROJECT.md` 中已填写的项目事实；未知内容从代码和工程配置中确认，不猜测。
- D2+ 选择构建/测试时先读取 `.ai-project/detected-capabilities.json`，把它当候选索引而非授权；项目配置变化后定向刷新，未确认的 Scheme、Configuration 和 Destination 不得猜测执行。
- 遵循现有语言、架构、目录、命名和依赖方式；不顺带重构无关代码。
- 优先最小完整修改；不新增未经需要证明的抽象、兼容层或第三方依赖。
- 所有 `Pods/` 及其他第三方依赖库源码均只读，包括 Swift Package Manager、Carthage 和手工引入的第三方源码。
- 修复应在 App 自有代码层完成；不得直接修改第三方依赖源码，也不得通过 `post_install`、自动 patch、脚本或其他间接方式规避这一限制。
- 确需上游修复时，先说明原因和影响，由用户决定；不得擅自修改。
- Objective-C 修改保留项目的 ARC/MRC、Nullability、KVO/KVC 和线程约定。
- Swift 修改遵循项目当前并发模式；只有遇到 actor、Sendable、async/await 或数据竞争问题时使用 `swift-concurrency`。
- 测试任务或现有测试需要调整时使用 `swift-testing`；不要为可逆低风险实现机械复制测试。
- D2-D4 中确有模拟器运行、权限、深链、截图、容器或日志证据需求时使用 `ios-simulator`；D0/D1 默认不使用。
- UI 修改保留可观察行为，并检查布局、导航、手势、键盘、动态字体、深浅色和 VoiceOver 中与改动相关的状态。

## 代码质量与注释预算

- 所有源码改动都使用表达业务意图的命名、保持职责清楚，并让注释解释原因或约束而不是复述代码；修改后删除或同步失效注释。
- D0 只检查注释真实性。D1 只对最终 Diff 做一次内联自检，不调用额外质量 Skill、不生成报告、不整理邻近历史代码。
- D2 读取 `.codex-rules/_shared/references/code-quality-contract.md` 和 [references/code-quality-ios.md](references/code-quality-ios.md)，只检查受影响文件的状态、错误、生命周期和必要注释。
- D3 在方案和最终 Diff 两个阶段使用上述规则，检查模块边界、公共接口、依赖方向和真实扩展点。D4 仅用于本次高风险路径，安全与发布证据优先，不借机重构。
- 格式、未使用符号和确定性静态规则优先使用项目已有 formatter、linter、编译器或 LSP；不得为质量检查自动安装工具。

## 完成条件

运行对应等级的最小充分验证。D0/D1 允许把运行验收明确交给用户，不因此生成阻塞报告；D2-D4 不得把“代码已写”“能编译”或“页面能打开”单独当作功能正确。通过后，只有新失败、范围扩大或未解决风险才扩大检查。

选择或扩大验证时才读取 [references/verification.md](references/verification.md)。只报告实际运行过的证据，并区分新失败、既有失败和未验证范围。

## 身份、任务隔离与证据

按 `.codex-rules/_shared/references/task-control.md` 核对当前工程身份。小任务轻量只读确认；D2+、并行、脏目录或交接使用唯一任务 ID，独立 baseline/context/handoff，恢复核对真实文件。禁改 Pods 和其他第三方公共库，禁止 post_install/patch 间接修改，不创建候选工程。最终区分代码修改、编译、自动测试、真机待验、Git 提交及推送；仅报告已执行内容，未执行不推导成功。

## 中文注释验收

每个新增/改动的自有函数或方法中文说明用途与适用的参数、返回值、异常、异步/线程/取消和副作用；成员变量、属性、常量中文说明用途、单位和状态语义。重要局部变量、计算步骤、算法与兼容分支解释原因和边界；简单下标不机械注释。同步更新失效注释，生成代码及第三方排除。最终 Diff 人工核对语义准确性，不把静态通过或注释行数当质量证明。详细契约按本等级加载共享 code-quality-contract，D1 仍在内联自检完成，不生成额外报告。

## 读取授权与覆盖

先核对 read-policy 再读取项目事实；身份、快照、上下文和报告共用白名单。未知或受限路径不打开、不遍历；链接和读取错误阻塞。部分范围只执行 D0 配置核验，不运行无法限制读取的外部工具，未检查范围明确写入报告。策略变化使旧证据失效。详见共享 read-boundary.md。

## 约束来源和生效范围

区分用户长期项目规则、当前任务范围及平台具体拒绝。一次只读/配置接入不代表永久业务禁读，临时范围放入任务 read-policy 而不是共享项目策略。新对话不继承已关闭任务的范围。平台拒绝操作保留暂停，未给路径时不编造目录禁令；目录访问授权不能替代平台审批，也不得换名重试旧拒绝操作。

## 2.6 分级与预算补充

难度、范围、风险独立记录；全 App 视觉改动不能按单处颜色处理。支付/登录短句先做高风险定向排查，只有证据证明纯文案/颜色才降级；权限、签名、构建配置不能因 JSON 后缀归 D0。D4 只验证本次能力，真正发布或签名才选择对应 Release/最终包/适用真机，不机械全 App 构建。简单任务仍在内存分级，不增加角色/任务文件/报告，不全仓扫描；身份使用已确认事实和精确配置，不运行会全树扫描的探测作为仪式。并行仅在用户/适用规则允许且独立切片收益超过协调成本时采用。
