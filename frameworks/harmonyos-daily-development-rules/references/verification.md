# HarmonyOS 分级验证

先发现项目已有的 `hvigorw`、模块、测试目录、脚本和 CI 命令，优先复用；不自动安装全局工具或替换 SDK。

## D0

- 检查差异和文件格式。
- 仅当配置、资源或模块元数据可能影响构建时运行解析或相关构建检查。

## D1

- 检查最终 Diff、ArkTS 语法、类型、装饰器和资源引用。
- 默认不启动模拟器、不运行 UI 自动化、不截图、不录屏、不新增测试、不生成独立报告。
- 只有存在实际编译风险且定向命令成本较低时，才构建受影响模块；否则由用户直接运行应用验收。
- 只有已有的快速测试能直接覆盖根因且运行成本低时才选择运行；不得为完成仪式新增机械测试。
- 最终简要标记用户运行验收尚未执行，不把它升级成阻塞或生成证据文件。

## D2

- 构建相关模块。
- 运行相关单元测试或组件测试；只有行为风险无法由静态检查或组件测试建立时，或用户要求时，才运行模拟器/UI 流程。
- UI 检查与改动相关的正常、加载、空、错误、恢复、路由返回和窗口适配状态。
- 涉及权限、后台、相机、文件、网络或系统服务时说明模拟器与真机证据边界。

## D3

- 每个切片先运行局部检查，集成后运行所有受影响模块测试。
- 验证公共接口、持久化兼容、生命周期、错误恢复和主要用户路径。
- 新依赖必须说明必要性、版本、许可证、隐私和替代方案。

## D4

- 按本次能力选择相关回归；真正发布或签名才使用对应 Release 构建、最终产物与适用真机证据。
- 账号、支付、权限、隐私、删除和数据迁移验证失败及恢复路径。
- 签名、发布、正式环境和真实交易不能用 Mock 代替；未执行时标记为未验证。

已通过的针对性检查只证明相应范围。D0/D1 不创建独立验收报告；最终回复中的一行检查说明即可。修复后只重跑被修改或被失败影响的检查，除非风险证据要求扩大。

## 本次中文注释人工验收

逐个核对本次自有函数/方法的中文用途与适用契约、成员/属性/常量的用途单位及状态、重要变量/计算/算法/兼容分支的原因与边界。修改与注释同步，生成代码/第三方排除。静态扫描只提供候选问题，语义准确性必须人工审查，不按注释行数验收；D1 在最终 Diff 内联完成。
