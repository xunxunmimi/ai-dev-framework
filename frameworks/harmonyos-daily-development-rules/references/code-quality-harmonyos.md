# HarmonyOS 代码质量补充

仅在 D2/D3 源码改动、D4 中相关高风险路径，或用户明确要求代码质量/架构/注释审查时读取。先应用共享代码质量契约，再应用以下 HarmonyOS 约束。

- 沿用项目已有模块、状态管理、路由和服务边界，不为局部功能引入第二套分层。ArkUI 组件负责展示和交互编排，网络、持久化和系统能力放在既有服务或 Adapter 边界。
- `@State`、`@Prop`、`@Link`、持久化状态及共享状态保持明确所有者，避免同一业务状态多份可写副本；派生状态优先计算而不是重复存储。
- `build()` 和渲染路径保持可预测，不执行网络、数据库或复杂系统副作用；生命周期、异步取消、页面退出和后台恢复写在对应边界。
- 使用 ArkTS 明确类型和稳定对象形状；跨进程、JSON、Native 或第三方 SDK 边界先验证数据，再转换为领域类型。
- 每个本次新增/改动的自有组件方法、函数和平台 Adapter 方法写中文用途说明及适用契约；重点说明状态所有权、线程/Sendable、权限、版本差异和失败恢复。
- 新接口、工厂、Provider 或中间层必须对应真实平台替换、模块隔离或测试边界；单实现且没有已知变化轴时优先直接实现。

最终自检只报告会影响理解、修改安全或实际扩展的事项；纯个人风格差异不阻塞完成。

## 本次中文注释检查

每个自有函数/方法说明用途与适用的参数、返回值、异常、异步及副作用；成员、属性和常量说明用途、单位与状态。重要局部变量/计算步骤与兼容分支解释意图、原因和边界。改动同步注释，排除生成代码/第三方。人工核对是否符合实际行为；静态规则不能证明语义准确，不按注释行数验收。
