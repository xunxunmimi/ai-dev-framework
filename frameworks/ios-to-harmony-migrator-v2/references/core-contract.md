# 核心契约

这些约束适用于所有等级，不能被精简验证覆盖：

- iOS 源目录只读；目标目录、缓存和证据不得写入源目录。
- 保留用户现有修改，先检查 Git 差异；不得用破坏性命令清理工作区。
- 不复制或记录密钥、证书、Token、真实账号、订单、正式域名和商户配置。
- 迁移以可观察行为等价为目标：状态、交互、导航、数据、错误和恢复优先于逐行翻译。
- `observed`、`inferred`、`unknown` 必须区分；Mock、编译通过和页面可打开不能单独证明等价。
- 平台无等价能力、产品行为变化或接受偏差必须登记决策；AI 不伪造用户批准。
- 验证失败不删除、不弱化断言、不改写为通过；只对实际验证范围使用 `verified`。
- 新的真机、测试或用户证据与 `verified` 冲突时，只重开受影响流程并保留冲突引用；不伪造通过，也不重置无关切片。
- 用户当前指令优先于框架建议，但不能扩大未授权的外部写入、付款、绑定、发布或数据破坏。
- 同一任务只能有一个主框架。`migration-transition` 中普通鸿蒙维护使用日常框架，迁移等价和缺失 iOS 行为才使用 V2。
- 旧脏改动必须与当前任务 Diff 分离；不得因项目历史、报告数量或未改动文件名提高当前任务等级。

项目偏好（主题、最低 API、目标设备、公共库、Git 提交策略）写入项目 `project.json`，不得升级为所有项目的框架硬规则。
