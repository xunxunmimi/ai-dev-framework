# Phase 0 源项目发现门禁

新迁移或新增未批准范围必须先完成源项目基线，不能一边猜测源行为一边开始鸿蒙业务实现。既有项目的普通 Bug、日常维护和已批准切片不要求倒退重做 Phase 0；源版本或迁移范围变化时只补受影响区域。

## 产物

- `ir/source-index.json`：脚本生成的完整文件索引、分类、内容哈希和工程信号。它是 L3 证据，默认不整份加载。
- `ir/discovery-baseline.json`：供决策使用的紧凑摘要，覆盖工程结构、架构模块、页面导航、交互状态、业务功能、依赖许可证、数据、网络、权限能力、资源本地化无障碍以及测试构建发布。
- `reports/discovery-gate.json`：门禁结果，只记录摘要和错误，不复制源码或长日志。

## 分析方式

1. 运行 `scripts/analyze_source.py <ios-source> <workspace>`，只读生成源索引和待填写基线。
2. 按区域阅读索引和必要源码。每个识别项标记为：
   - `mapped`：已经理解并写明 HarmonyOS 目标策略；
   - `excluded`：明确不迁移且有原因；
   - `unknown`：尚未解决，必须标记风险。
3. 每个区域记录摘要、证据指针和覆盖计数。`sourceFilesAccountedFor` 表示已通过区域、目录或条目归属覆盖，不要求把每个文件内容复制到基线。
4. 阻塞型 unknown 必须解决；非阻塞型 unknown 必须绑定后续切片。同步 `analysedSourceIndexSha256` 后运行门禁。
5. 门禁通过后生成迁移计划，并把报告中的两个 SHA-256 写入计划 `discovery` 字段，再请求用户批准。

映射项的 `details` 至少回答当前区域不可缺少的问题：

| 区域 | 必填信息 |
|---|---|
| 工程结构 | Targets、入口、Build Configuration |
| 架构模块 | 职责、依赖方向 |
| 页面导航 | 页面状态、导航和弹层关系 |
| 交互状态 | 触发方式、状态变化、失败与恢复 |
| 功能链路 | 入口、成功、失败、取消/恢复 |
| 三方依赖 | 版本、用途、许可证、鸿蒙替代 |
| 数据存储 | 存储位置、Schema、迁移、安全边界 |
| 网络后端 | 契约、鉴权、错误、重试与取消 |
| 权限能力 | 能力、触发时机、拒绝与恢复 |
| 资源体验 | 资源、本地化、无障碍 |
| 工程发布 | 构建、测试、签名与发布 |

## 硬门槛

- 11 个分析区域必须为 `complete` 或有证据的 `not_applicable`。
- 完成区域至少有一个可追溯条目，覆盖数必须与实际 disposition 一致。
- 索引文件必须全部归属，分析哈希必须等于当前源索引哈希。
- 不允许遗留阻塞型 unknown；低风险 unknown 必须有解决切片。
- `plan_approval.py approve/check` 会重新运行门禁。基线、源索引或迁移计划任一变化都会使旧批准失效。

不要为“分析完整”把整个 iOS 工程放进单次上下文。先读基线和分类统计，再按区域、入口及直接调用链读取源码；原始索引和运行证据只在核对时按需读取。
