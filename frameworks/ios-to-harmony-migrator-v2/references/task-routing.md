# 任务分级与自动升级

## 分级

| 等级 | 范围 | 默认上下文 | 默认验证 |
|---|---|---|---|
| T0 | 文档、注释、非运行配置 | 核心契约、改动文件 | 格式/Schema/静态检查 |
| T1 | 单点 Bug、局部样式或文案，影响明确 | 核心契约、当前状态、相关文件 | Diff；必要时静态/定向编译；运行验收交给用户 |
| T2 | 新页面、组件、普通功能，或导航/状态/持久化行为修改 | 加载对应 UI/平台规则和调用方 | 相关测试；模拟器/设备按行为风险选择 |
| T3 | 新迁移切片、公共接口、依赖或跨模块 | 加载迁移工作流和受影响矩阵 | 构建、契约、相关设备与共享回归 |
| T4 | 发布、全量里程碑、高风险数据/身份/支付 | 加载全部适用发布规则 | 全门禁、全回归、适用真机/人工检查 |

## 自动升级

- 修改公共基类、路由根、存储 Schema、依赖或构建配置：至少 T3。
- 支付、账号归属、安全存储、数据库迁移、签名和发布：T4。
- 影响文件超过 8 个或覆盖 3 个以上模块：至少 T3。
- 两次定向修复未解决同一问题、依赖边界不清或出现新回归：升级一级。
- 只有发布前、计划里程碑或真实跨切风险才升级到全量回归。

分类器先自行判断，用户无需声明任务大小；用户明确指定验证方式时遵从用户要求。局部文案、颜色、间距、样式、空值和影响明确的 Bug 默认为 T1。新增完整页面或功能，以及导航、路由返回、持久化、权限、共享状态和异步恢复行为至少 T2；迁移等价切片为 T3。

`migration-transition` 中“iOS 一致性”、“与苹果端不一致”、“源项目行为缺失”均是迁移等价意图。一次包含多处/多项/批量或明确数量的反馈时，设为 `parity-batch` T3：先联合诊断共享根因，再拆成可独立验收的 T1/T2/T3/T4 切片。明确“不涉及 iOS 一致性/迁移等价”时不误路由到 V2。详细方法见 [parity-residuals.md](parity-residuals.md)。

采用 `pre → post → final` 三阶段判断：`pre` 只看请求和直接事实，`post` 在检查调用链后允许升降级，`final` 只使用本任务文件和最终 Diff。任务开始时保存 `task-baseline.json`，旧脏改动进入 `excludedPreexistingChanges`，不得用于抬高等级。文件名中的 `Payment`、`Release` 等不能单独触发 T4；只有本任务实际改变支付、账号、安全、数据迁移或发布行为时才升级。

T0/T1 默认不启动模拟器、不运行 UI 自动化、不截图、不录屏、不新增测试、不生成独立报告。最终只简要说明改动和最小检查，并标记运行验收由用户完成。发现影响范围扩大时再升级。

T2-T4 任务结束后记录实际等级、升级原因、执行门禁和未验证项。分类器是建议器；代码事实与风险证据可以覆盖其结果，但要记录原因。T0/T1 不为了记录流程额外创建任务报告。

新迁移和新增未批准范围在进入 T2-T4 业务实现前必须通过 Phase 0 发现门禁及计划批准。既有已批准切片、迁移过渡期普通维护和不改变迁移范围的局部 Bug 不重复执行 Phase 0；源索引变化时只重分析受影响区域并重新绑定批准。

## 代码质量与注释预算

- T0 只检查注释真实性；T1 对最终 Diff 做一次内联自检，不加载完整质量规则、不调用通用质量 Skill、不生成报告。
- T2-T4 源码任务读取项目 `.migration-v2/references/code-quality-contract.md` 和 `references/code-quality-migration.md`。T2 只检查受影响文件；T3 在方案和最终 Diff 检查边界、公共契约与真实变化轴；T4 以安全、数据和发布风险为先。
- 质量检查只覆盖本任务 Diff，不顺带重构历史代码。机械规则使用项目已有 formatter、linter、编译器或 LSP，不自动安装工具。

## 外部能力自动路由

任务等级控制调用上限，任务类型和证据缺口决定是否调用；不得把某个等级直接等同于某个工具。

### 蓝湖 MCP

- 仅当项目 `externalTools.lanhu` 未禁用，并且本次提供蓝湖链接或 `projectUrl` 已配置时考虑调用。
- T1 的颜色、字体、间距、圆角、图标、切图等局部视觉问题只读取一个目标区域。
- T2 的新页面、组件或视觉还原只读取目标页面总览、必要区域和素材。
- T3 只读取当前迁移切片，不扫描整个蓝湖项目；T4 默认复用已有证据，除非 UI 发布阻塞明确缺少设计证据。
- 当前 iOS 可观察行为默认优先；只有 `authority=primary` 或用户明确指定时，蓝湖新设计覆盖旧行为。调用保持只读，禁止自动发布、编辑、删除留言或发送通知。
- 普通逻辑、编译、数据、导航、权限和状态问题不因位于“页面”中而调用蓝湖。工具或凭据不可用时继续使用现有截图、代码和项目资料，不阻塞任务。

### Ponytail Review

- T0/T1 默认关闭；T2/T3 完成实现和必要验证后才检查最终 Diff，T4 默认关闭。用户明确要求复杂度审查时可以覆盖默认值。
- 一个强信号即可触发：新增依赖、单实现抽象/工厂、重复实现平台能力、为局部功能新增完整中间层。
- 两个普通信号也可触发：多个无必要包装层、未使用扩展点、重复帮助函数、实现范围明显超出请求。
- 触发后最多调用 `$ponytail-review` 一次。它只审查复杂度，不替代正确性、安全、性能、迁移等价或发布验证；不得删除必要兼容层、错误处理、可访问性和平台适配。
- 只采纳能够证明不改变可观察行为的建议；如有修改，重跑受影响的最小检查，不循环审查。
