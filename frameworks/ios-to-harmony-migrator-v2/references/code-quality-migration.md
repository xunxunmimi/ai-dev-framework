# 迁移代码质量补充

用于 T2-T4 的迁移实现和等价遗留修复。先应用项目 `.migration-v2/references/code-quality-contract.md` 中的共享契约，再应用以下迁移约束。

- 以 iOS 可观察行为和业务语义为输入，按 HarmonyOS 能力重新建立清晰边界；不要逐类复制 iOS 架构、命名和临时兼容层。
- 页面、状态、领域逻辑、数据访问和平台 Adapter 的边界必须能说明其必要性。平台差异集中在 Adapter 或明确映射处，不散落到多个 UI 组件。
- 迁移注释只说明非显然的源端契约、已确认的平台差异、兼容窗口和回退策略；不要粘贴 iOS 实现、迁移历史或逐行对照说明。
- 等价所需的特殊分支必须能追溯到源行为、产品确认或已登记偏差。临时分支写明移除条件，不能永久保留模糊的“兼容处理”。
- 公共模型、存储 Key、请求字段、错误语义、顺序、重试和取消策略优先保持稳定；平台命名可本地化，但不能改变业务含义。
- 新抽象只有在真实跨平台语义、多个实现、模块隔离或可替换系统能力边界存在时才引入。迁移规模本身不是增加层级的理由。

质量自检不得替代迁移等价、设备能力、真机、高风险链路和发布验证，也不得为了“结构更漂亮”改变已验证行为。
