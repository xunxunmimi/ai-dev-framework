# UI 与交互质量

## 两种验收范围

- T1：默认不启动模拟器/设备、不截图、不录屏、不运行综合评分；检查局部实现和资源引用，运行验收交给用户。发现导航、状态恢复、权限、生命周期或共享组件影响时升级到 T2/T3。
- T2：验证受影响页面和状态；只有静态/单元检查不足以建立行为、风险需要或用户要求时才运行标准设备，不默认启动多台设备。
- T3/T4 或 UI 里程碑：标准设备实测；关键页面增加窄/宽设备或等价真实设备证据，并运行综合评分。

先冻结源端页面结构、Safe Area、字体、图片 Content Mode/Cap Insets、状态、动画、手势、键盘、弹层、导航返回和生命周期。真实业务资源不能用 Emoji 或近似符号替代。

UI 切片开始时用 `scripts/ui_state_manifest.py add` 建立页面状态清单；里程碑评分前用 `check` 确认每个适用状态都有源端和目标端真实证据。`not_applicable` 必须写原因，不能通过删除困难状态提高分数。

## 加权验收

使用 `scripts/score_ui_quality.py --state-manifest <ui-state-manifest.json>` 计算 0–100 分。状态清单不完整时，即使人工类别分数超过 90 也不得通过：

| 类别 | 权重 |
|---|---:|
| 页面结构与核心区域 | 25 |
| 字体、颜色与真实资源 | 20 |
| 交互与状态转换 | 20 |
| 动画与生命周期 | 15 |
| 导航与返回恢复 | 10 |
| 几何细节 | 10 |

里程碑默认总分必须至少 90，且任一类别不得低于 75。评分必须引用截图、录屏、UI 树或测试证据，不能凭空填写。

## 对照原则

- 几何值用于定位偏差，不把跨平台字体栅格化差异当布局失败。
- 文本检查实际字形边界、Baseline、行高、换行和截断；不要只比较字号数字。
- 截图采用结构区域和显著性对比；严格 RGBA 只用于相同渲染条件或资源本身。
- 动画比较开始/结束状态、时长、曲线、暂停恢复和可见性生命周期。
- 关键旅程应双端回放并比较页面顺序、状态、反馈、错误和恢复。

## 2.6 证据合同

旧路径清单不再被当作已验证。独立预期覆盖的摘要须进入批准计划，check/score 提供 --project、--task-id、--expected（及相同 profile/slice）；证据记录内容摘要、构建、设备/状态、时间和捕获来源。缺页/删状态/重复/无批准豁免/陈旧证据均阻塞。脚本只验证覆盖与来源合同，人工分数不是自动视觉核验。完整字段见 docs/2.6.0-分级优化与回滚.md。
