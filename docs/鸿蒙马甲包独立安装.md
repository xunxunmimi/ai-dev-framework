# 独立马甲包 Skill 启动

新目标在制作和验收期间只装马甲包 Skill，不装日常框架。此入口只安装指导文件和选择记录，不运行应用、创建正式任务协议或宣称验收成功。Codex 后续依照 Skill 和真实授权执行制作；不得把安装成功当作业务测试完成。

1. 源／目标使用分离的真实规范目录，分别有来自所有者的读取策略。完整预检会检查所有已知控制路径及安装所需权限；缺项就准确报告，不自动生成或扩大策略。
2. 只读预检：
   `python3 installers/bootstrap_harmonyos_restyle.py --project /absolute/target --source /absolute/source`
3. 核对结果，确认所有源／目标相关写入者已停止。用本次摘要和真实确认来源执行：
   `python3 installers/bootstrap_harmonyos_restyle.py --project /absolute/target --source /absolute/source --apply --plan-sha256 <plan.planSha256> --offline-writers-stopped '<真实停写确认来源>'`
4. 在目标项目明确调用 `$harmonyos-app-reimplementation`，提供 Logo、参考图、原项目、目标项目和授权范围。功能／逻辑／底层实现保持，重做自有 UI、icon、新类和方法名；原文案及受保护输出布局不变。
5. 实际完成并验收后，才另行明确接入日常开发框架。没有自动交接，也没有伪造验收记录。

入口按 update→tasks→Skill 安装锁排序，锁内及发布前复核计划。锁不能阻止协议外 writer，确认来源不是身份认证。拒绝已有主框架、AGENTS、任务、升级或暂停记录；不能卸载旧框架假装新项目。对于已经安装日常框架的目标，本入口仍 fail-closed，需另做受控交接。

发布使用同一目录暂存后重命名，既有目标 Skill 不覆盖。失败可能留下空父目录或锁文件，但不会删除业务内容。发生异常先核结果，不盲目重复安装；若 Skill 已存在，停止并检查原选择与文件。

## `.agents` 缺失和读取范围未授权不是同一问题

对于全新目标，安装器会在显式 `--apply` 时自动创建已获准但物理上不存在的 `.agents`、`.agents/skills`，无需手工建目录。只读预检不会创建它们。

首次确认项目读取策略之前，可先列出本版本安装所需的精确候选范围：

```bash
python3 installers/bootstrap_harmonyos_restyle.py \
  --project /path/to/new-harmony-project \
  --source /path/to/original-project \
  --print-required-read-scope
```

此命令只读取当前框架发行包，不访问源或目标项目，也不创建或修改策略。输出包含两个父目录检查、安装锁、维护锁、已有控制状态检查，以及 Skill 的精确文件/目录。交由策略所有者在首次确认时审阅；源项目仍需要独立的读取授权，读取范围不等于写入授权。

若错误为“安装前置路径未授权或被明确拒绝”，安装器尚不能检查该路径是否存在。手工创建目录无法解决权限问题。已有策略由所有者按正式流程补全或调整，工具不会自动追加 `.agents/**`、忽略 deny 或覆盖已有规则。范围确认后重新执行正常预检，再按当前计划摘要显式安装。已安装日常框架的目标仍需要正式交接，本功能不会卸载或转换它。
