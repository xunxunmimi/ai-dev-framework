# 可选 Skill：鸿蒙应用独立重实现（马甲包）

源码放在 `capabilities/harmonyos-app-reimplementation/`，不是单独一套主框架，也不放进旧迁移项目或所有项目的通用规则。保留最新 main 的主框架版本，本次新增能力不自动升级任何项目。

适用：有权使用的原鸿蒙项目，功能、业务逻辑与所有文案保持一致，同时基于一张 Logo 和几张参考图重新设计全量 UI，并独立重写自有实现。品牌替换/代码重构与独立重实现是不同工作；本 Skill 不承诺审核规避或上架结果。

## 一次按项目接入

目标先使用 `setup-project.sh harmony-daily` 接入鸿蒙日常主框架。原/目标目录必须已经存在且互不包含。按用户真实授权准备两项目的 `.ai-project/read-policy.json`；路径本身不是授权，安装器不会创建或放宽策略。允许范围须包含目标技能目录和安装锁，源策略只读。窄策略可安装，但任务仅能分析获准内容，缺失覆盖不得称全量完成。

从框架源码目录执行，默认只预览：

```bash
python3 installers/enable_harmonyos_reimplementation.py \
  --source /path/to/original-harmony-project \
  --project /path/to/new-harmony-project
```

已明确授权该项目接入且预览无误，同一命令加 `--apply`。安装仅新增目标 `.agents/skills/harmonyos-app-reimplementation/` 及自身锁；不改源代码、不改 AGENTS.md、不改生命周期/主框架版本，不访问设备或网络。已有同名技能拒绝覆盖，升级须检查本地修改后单独处理。缺策略时按主框架读边界处理，不能伪造 `confirmed` 或复制其他项目策略。

安装不是授权扩大器。后续任务执行仍检查源和目标当前策略；selection 中的摘要是安装时基线，策略变化必须重新核对，不复用旧权限。迁移控制文件缺失不是本 Skill 自动触发 iOS 迁移初始化的理由。

## 使用时这样说

在目标项目新任务或现有相关任务里明确指定：

> 使用 $harmonyos-app-reimplementation。原项目是 …，目标项目是 …。功能、逻辑、多语言和文案保持一致，自有代码独立重实现；根据附带的 Logo 和参考图生成全量新 UI、布局及 icon。先完整分析，再实施和真机验收。项目配置尚未提供的地方先留明确占位。

这会启动分析与实现流程，不是一句命令自动生成可验收完整产品。提供源/目标和图片后可开始；只有确实阻塞的授权、合同或方向冲突才提问，配置阻塞不应暂停其他页面/逻辑实现。若还未安装，先明确选择项目并按上面安装；只有下载框架并不会全局激活。

输出：行为/文案合同、视觉系统、实现与外部合同例外映射、逐项验证/未测清单、可追溯源码与产物。默认以正常字号真机核验。底层 SDK、系统 API、服务端字段、数据兼容、许可声明允许保留，不为改名破坏合同。

停止使用：把本项目 selection.json 的 `enabled` 改为 false，并停止相关任务。其他项目不受影响。只有独立重实现请求触发；普通 Bug、iOS 原样迁移、局部 UI 修复继续使用原主框架。

## 维护者验证

```bash
PYTHONDONTWRITEBYTECODE=1 python3 -B installers/harmonyos_reimplementation_self_test.py
```

测试使用临时合成目录，无真实项目/设备/网络副作用。安装与文档验证不能证明实际 App 功能/视觉验收通过。此能力随源码提交发布；没有另行发布二进制框架版本，也不修改历史导入来源记录。
