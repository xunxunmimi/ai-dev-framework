# 可选 Skill：鸿蒙马甲包制作

源码放在 `capabilities/harmonyos-app-reimplementation/`，不是单独一套主框架，也不放进旧迁移项目或所有项目的通用规则。保留原能力 ID、安装和文档路径以兼容现有引用；合入源码不自动升级任何项目。

适用：明确授权的鸿蒙马甲项目。统一保留原功能、业务逻辑、底层实现和文案；新建自有类、更新类名和方法名，按参考重做全部自有页面 UI 和图标。受保护的输出布局默认保留，按项目记录获批例外、SDK/API 及依赖；本 Skill 不用于规避审核，也不承诺上架。

## 历史接入方式（不适用于新的独立马甲项目）

目标先使用 `setup-project.sh harmony-daily` 接入鸿蒙日常主框架。原/目标目录必须已经存在且互不包含。按用户真实授权准备两项目的 `.ai-project/read-policy.json`；路径本身不是授权，安装器不会创建或放宽策略。允许范围须包含目标技能目录和安装锁，源策略只读。窄策略可安装，但任务仅能分析获准内容，缺失覆盖不得称全量完成。

从框架源码目录执行，默认只预览：

```bash
python3 installers/enable_harmonyos_reimplementation.py \
  --source /path/to/original-harmony-project \
  --project /path/to/new-harmony-project
```

已明确授权该项目接入且预览无误，同一命令加 `--apply`。安装仅新增目标 `.agents/skills/harmonyos-app-reimplementation/` 及自身锁；不改源代码、不改 AGENTS.md、不改生命周期/主框架版本，不访问设备或网络。已有同名技能拒绝覆盖，升级须检查本地修改后单独处理。缺策略时按主框架读边界处理，不能伪造 `confirmed` 或复制其他项目策略。

安装不是授权扩大器。后续任务执行仍检查源和目标当前策略；selection 中的摘要是安装时基线，策略变化必须重新核对，不复用旧权限。迁移控制文件缺失不是本 Skill 自动触发 iOS 迁移初始化的理由。

## 使用时这样说

在目标项目新任务或现有相关任务里明确指定：

> 使用 $harmonyos-app-reimplementation。原项目是 …，目标项目是 …。保留原功能、实现、业务逻辑、多语言和文案，新建自有类、更新类名和方法名；按附带的 Logo 和参考图重做全部自有页面 UI 与图标。受保护的输出布局、允许例外及目标 API 如下：…先完整分析，再实施和真机验收。项目配置尚未提供的地方先留明确占位。

这会启动分析与实现流程，不是一句命令自动生成可验收完整产品。提供源/目标和图片后可开始；只有确实阻塞的授权、合同或方向冲突才提问，配置阻塞不应暂停其他页面/逻辑实现。若还未安装，先明确选择项目并按上面安装；只有下载框架并不会全局激活。

输出：行为/文案合同、视觉系统、实现与外部合同例外映射、逐项验证/未测清单、可追溯源码与产物。默认以正常字号真机核验。底层 SDK、系统 API、服务端字段、数据兼容、许可声明允许保留，不为改名破坏合同。

停止使用：把本项目 selection.json 的 `enabled` 改为 false，并停止相关任务。其他项目不受影响。只有明确选择鸿蒙马甲制作才触发；普通 Bug、iOS 原样迁移、局部 UI 修复继续使用原主框架。

## 旧项目与固定快照兼容

本次规则调整改变套件内容摘要，使用新的候选源码版本。任务运行器、协议和状态格式不变，不能在活动任务下直接替换套件。历史 intent 不授予重写权限，安装器仍拒绝覆盖现有项目 Skill；既有项目继续使用当前快照，具体任务遵循用户明确的新规则。

- 项目 `suiteRoot` 指向固定快照：拉取源码仓库不会改变旧快照；旧版本继续运行。新 pin 使用版本 + 内容摘要生成不同目录，不覆盖旧 pin。
- 项目 `suiteRoot` 指向可变 Git 检出：直接 pull 会使已安装清单与套件版本/摘要不匹配，运行器按设计阻止继续；即使只新增可选 Skill 也会如此。先保留旧提交对应的固定来源，不修改旧任务基线；按既有审计/离线升级流程处理。
- 准备升级时先停止相关 writer，运行 `audit-project.sh` 与 `update-project.sh --dry-run`。活动任务、未释放执行或本地修改仍按原门禁处理，不能改清单摘要、假装任务关闭或使用首装覆盖。
- 仅 README 变化不进入 `suite_digest`，但进入 pin 文件清单；`capabilities/` 和 `installers/` 变化进入套件摘要。pin 校验发现内容变化仍会拒绝复用。

历史快照按确切提交和摘要审计，不把新规则合入视为旧项目已升级。
