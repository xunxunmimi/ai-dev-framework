# 2.6.5 任务专用安全引导

当项目没有长期 `.ai-project/read-policy.json`，又没有共享身份时，可按真实用户授权为单个任务指定精确普通文件及必要身份配置；不创建长期策略、共享身份或安装清单。如果长期项目策略已存在，该入口拒绝使用，必须遵守现有策略。禁止用它绕过任何长期或平台限制。

在项目外的安全位置准备 JSON，字段见 `shared/schemas/task-only-bootstrap.schema.json`。`projectRoot` 为已核实的真实绝对路径，`taskId` 唯一；`authorizationSource` 记录真实授权来源，不是身份认证或平台批准；`allowFiles` 是明确允许读取的精确相对文件，`identityFiles` 与 `editableFiles` 必须是其子集。`denyDirectories` 列出本任务明确禁止的精确目录（例如 `.test`），不得与允许文件重叠；此排除仅属于该任务。不要使用通配符、目录作为允许文件、凭据、私有文件或未确认安全的身份配置；必要身份值放在 `identitySelection`，不得放秘密。`confirmed` 只有获得真实用户授权后才可为 true。工具不会自动发现所有秘密。

以固定版本运行，任务文件每个单独指定一次 `--file`，必须与 `editableFiles` 完全一致：

```sh
python3 <固定套件>/shared/task-routing/task_runtime.py init --project <项目真实绝对路径> --task-id <ID> --task-only --task-only-spec <授权JSON绝对路径> --file <相对文件1> --file <相对文件2> --request <本次需求>
python3 <固定套件>/shared/task-routing/task_runtime.py resume --project <项目真实绝对路径> --task-id <ID> --task-only
```

合成示例和完整字段见 `shared/task-routing/task_only_self_test.py`。实际支付任务按授权填齐全部九个文件和已确认不含秘密的身份文件；不是仅填两个示例文件。身份、策略和不可变基线保存在该任务目录；不读取或遍历白名单外业务文件。为任务冲突检查仅使用其他任务的 `state.json`；不读取其附件。策略、身份或范围变化会阻塞恢复；长期项目策略后来出现也阻塞，不自动绕开。

任务覆盖始终为 partial，Git 修订及已有改动未核验；不运行原工程 Git、构建或测试，已有改动必须人工检查。进程内配置检查只证明声明范围，不能当作功能或全项目通过。外部构建与模拟测试只能在确认无真实凭据、无外链的隔离副本中执行，报告仅绑定该副本。

回写继续使用 2.6.4 的 `installers/controlled_task_write.py`，按 `2.6.4-部分范围受控回写.md` 制作计划和备份事务，并在预览及应用命令加 `--task-only`。先确认原工程任务状态、原文件和隔离候选完整哈希，复核差异后应用；成功后人工复核并调用 `checkpoint --task-only`。异常、中断及用户后续编辑遵守事务恢复和漂移拒绝规则；不要将隔离报告改成原工程验证通过。
