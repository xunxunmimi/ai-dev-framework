# 未开任务日常安装的显式独立 Skill 交接

此入口只适用于已经安装日常框架、尚无任务/身份/操作记录，而且生成的控制文件仍完全符合独立验证旧版本的目标。新项目继续用 `bootstrap_harmonyos_restyle.py`，无需本流程。

## 范围和必须满足的条件

- 源/目标为独立真实目录，不接受别名或相互包含。源始终只读。
- 使用独立校验的旧 2.6.14 源快照，以及准确的 `2.6.15-standalone-restyle-rc1` Skill 快照。运行工具本身是 2.6.17；不要替换旧项目 pin，也不要把新工具版本冒充 2.6.15 的能力载荷。
- 平台权限、所有者对每一阶段精确路径/摘要的批准、全部写者确已停止的证据必须在调用前取得。命令行输入只是记录证据，不生成权限。三把锁暂时空闲不构成停写证明。
- 仅更新生成的治理元数据和指定 Skill；不会修改业务代码、应用配置、原项目、现有任务或历史报告。已有人工修改的 AGENTS 内容不覆盖。
- 预先选定 32 位小写十六进制 nonce。暂存与回滚隔离路径由 nonce 固定，与策略摘要无关；最终计划仍绑定完整策略和字节摘要。
- 若读取策略需要新增范围，只允许正式审阅的精确增量，保留原 deny、先归档原字节，不以 `.agents/**` 扩权。

## 操作顺序

以下为参数模板，替换为已验证资料。所有 preview/plan 输出应由操作方保存在目标之外；工具不会自动保存或批准它。

1. **只读范围预览**：

```bash
python3 installers/restyle_scope_cli.py \
  --project "$TARGET" --nonce "$NONCE" \
  --policy-before-sha256 "$OLD_POLICY_SHA" preview
```

2. 核对 `exactReadAdditions`、前后策略摘要及外部权限。明确批准后，用同一入口的 `register` 子命令提供 `--policy-after-sha256`、`--installation-manifest-sha256`、`--owner-approval-reference`、`--writer-stop-evidence`，并为每个批准路径重复 `--approved-exact-path`。**原策略先被持久归档，再登记新策略**。此步骤独立于后续交接事务；回滚交接不会自动撤销已批准的读取范围。

3. **固定载荷暂存预览**：

```bash
python3 installers/restyle_transition_cli.py --project "$TARGET" stage-preview \
  --source "$SOURCE" --new-pin "$VERIFIED_2_6_15" \
  --new-pin-sha256 "$NEW_PIN_SHA" --nonce "$NONCE" \
  --manifest-sha256 "$OLD_MANIFEST_SHA"
```

核对所有 `writePaths` 与摘要后，将 `stage-preview` 换成 `stage`，追加 `--approved-plan-sha256`、`--owner-write-approval-reference`、`--writer-stop-evidence`。仅创建固定已授权目录、日志设施及准确载荷，排他写入，不覆盖。它不激活 Skill、不改应用。**中断留下部分暂存时立即阻断，不能盲目重试或删除；先审阅残留。**

4. **只读交接计划**：同样提供 source/new-pin/nonce/manifest 参数，子命令改为 `plan`，追加 `--old-pin`、`--old-pin-sha256`、`--writer-stop-evidence`。若旧清单引用已独立证明的目标内历史 pin，另外提供 `--historical-pin-path` 和 `--historical-pin-evidence`。该模式只核对历史字符串与外部可信旧副本，不读取或声称重新验证目标内旧 pin 的字节。

5. 将返回的 **`record` 对象本身** 保存到目标之外的普通文件，不要保存整个外层输出作为 record。由所有者审阅计划摘要和全部 `requiredWritePaths`。显式执行：

```bash
python3 installers/restyle_transition_cli.py --project "$TARGET" apply \
  --record "$REVIEWED_RECORD" --approved-plan-sha256 "$PLAN_SHA" \
  --owner-write-approval-reference "$APPROVAL_REFERENCE" \
  --writer-stop-evidence "$CURRENT_STOP_EVIDENCE" \
  --approved-write-path "$EXACT_PATH_1" --approved-write-path "$EXACT_PATH_2"
```

最后一组选项必须覆盖计划中的全部精确路径，不能用通配符代替。工具按 update → tasks → Skill 锁顺序复核，先持久记录，再停用旧日常协议，更新生成的路由/生命周期，排他发布 Skill，全量验证后才记录完成。所有回执仍声明不授予应用执行权限。

6. 需要回滚时，用同一 record、摘要、逐项写入批准和**当前**停写证据，将 `apply` 改为 `rollback`。准确 Skill 以原子 no-clobber 改名保留到固定隔离目录，恢复路由/生命周期，最后恢复旧清单。隔离后的中断可验证重放。任何字节漂移、未知材料均阻断；隔离资料清理是另一个需要审阅的操作，不递归删除活动 Skill。

制作完成/验收后接入日常框架仍是另一个明确交接，本工具不自动认定验收完成。

## 验证

无外部工程依赖的范围/日志/发布测试可直接运行。跨版本端到端用临时目标和独立版本快照：

```bash
export RESTYLE_TEST_OLD_PIN=/path/to/verified-2.6.14
export RESTYLE_TEST_NEW_PIN=/path/to/verified-2.6.15
export PYTHONPATH=installers:shared/task-routing
python3 -B installers/restyle_transition_cli_self_test.py
python3 -B installers/daily_restyle_transition_self_test.py
```

未提供快照时跨版本测试明确 skip，不算验证通过。Linux 合成测试不等于原生项目或真机验收，发布本版本不会部署或转换任何项目。
