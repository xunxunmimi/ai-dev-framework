# 离线保留任务升级（2.6.13 候选）

适用于已登记协议 2、尚有 active / blocked / waiting-permission 任务，但所有写入者可停下来的项目。原任务 ID、状态、权限等待、归属、业务文件、基线、检查点、交接和历史报告保持不变。升级不重新领取或释放任务，也不会移动正在执行的进程。原验证结果仍绑定旧规则；新版运行器恢复任务时将不同绑定的结果视为过期，不将其当作新规则已验收。

## 操作

1. 保存可校验的旧套件目录，另选独立的目标套件目录；不要在原固定目录上 pull 或覆盖。以下命令从目标套件根运行。
2. 停止并确认所有旧/新运行器、业务编辑、后台构建和验证子进程，无实际写入者。锁空闲不等于进程已退出；若不能核实，不要升级。
3. 只读预演：`./installers/update-project.sh /绝对路径/项目 --dry-run`。检查 `audit.preserveTaskStatePlan` 的任务列表、状态、受管文件和目标标识。未给出 `audit.preserveTaskStatePlanSha256` 时，不执行保留模式。
4. 使用本次摘要和可复核停写来源执行：

   ```bash
   ./installers/update-project.sh /绝对路径/项目 --preserve-task-state-plan-sha256 <本次摘要> --offline-writers-stopped '<本次确认来源>'
   ```

5. 核对输出版本与事务记录。用**项目已安装的新运行器**按原 ID 执行只读 `resume` 检查；原本存在的业务越界、身份/配置漂移、检查点冲突或权限等待仍须按原流程处理。不要自动重发操作。

## 停写与恢复边界

- 安装器持项目和任务锁，检查验证锁及持久执行记录；schema 不支持、未知来源、基线不一致、受管文件漂移、停写不明确均阻断。协议外的旧 writer 不受这些锁控制。
- 事务日志先保存规则前像和计划，再临时关闭安装清单门禁；最后替换正式清单。只有从原基线或上次确切承接的哈希到本次目标哈希的标准受管路径才可承接；其他规则或业务变化不因此得到认可。
- 遇到异常时先核对任务、锁与文件，无变化才自动恢复。断电或无法自动恢复时，保持所有写入者停止，用原事务目录显式恢复，不能用重新 setup 覆盖：

  ```bash
  python3 installers/project_framework.py restore /绝对路径/项目 --suite "$PWD" --transaction <本次事务目录> --offline-writers-stopped '<本次确认来源>'
  ```

- 恢复只恢复本次安装文件，不是任务数据回滚。事务后新增/修改任务、基线、读取策略，或旧套件内容改变，都会拒绝恢复；不要强制清锁、改状态或手动更换清单。
- 任务原文不进入升级事务或 Git。事务保留本地受管文本前像、任务 ID/状态和摘要，应按原项目权限保管。
