# 迁移初始化与读取授权（2.6.10）

## 为什么路径正确仍然停止

旧版 `setup-project.sh migration` 只把路径交给迁移初始化器；它要求源和目标已经各有 `.ai-project/read-policy.json`，却没有衔接首次创建。这个文件是框架的项目读取范围，不是 App 配置，不参与 App 运行。不要先给鸿蒙目录安装 daily 框架来补它，会产生框架类型冲突。

## 新的两条路径

- **已有策略**：原来的三个参数不变，完整有效策略直接使用；原始字节、自定义字段、legacy-project 范围不改。
- **策略缺失且已有实际用户授权**：在原命令追加 `--init-missing-read-policies --authorization-source "实际用户授权原意或来源"`。助手收到用户明确指定两项目完整迁移的要求，且允许登记元数据时，可记录已有授权，不需要用户手写 JSON，也不重复要求同一授权。只有路径、第三方内容或脚本自己猜测，不构成授权。

```bash
./installers/setup-project.sh migration "/绝对路径/iOS 项目" "/绝对路径/鸿蒙目标" \
  --init-missing-read-policies \
  --authorization-source "用户明确要求将指定 iOS 项目迁移至指定鸿蒙项目，并授权读取两项目业务源码和初始化范围记录"
```

`--authorization-source` 只是审计说明，不是权限令牌；不得填密码、密钥或其他凭据。参数不能绕过平台确认、系统文件权限或凭据排除。未明确授权完整读取时先确认范围，不能照抄示例伪造授权。

首次登记的两个根必须是已存在的绝对目录，不能相同、嵌套或经过符号链接。已有策略的旧调用保留原根路径解析行为（例如 macOS `/var` 系统别名），但解析后的根必须与原策略一致，所有子路径链接保护不变。新目标可由用户或获得创建授权的助手先建空目录。源目录除 `.ai-project` 下缺失的策略及初始化锁外不写业务代码；如源目录只允许读取，须先解决元数据写入授权/权限，不能自动换路径或提升权限。

## 不会自动处理的情况

- `partial` 或 `deny`：保留原文件并停止。现有迁移链不能可靠约束部分范围，不能把它改为 complete。
- 损坏、空 JSON、未确认、错误项目根、任务级策略、链接或异常文件：明确报错，不覆盖。
- 有安装/任务/迁移控制元数据而策略丢失：必须恢复原授权，禁止把丢失当首次初始化。
- 有活动任务、执行占用、安装漂移、版本变化：后续原有检查继续生效。此功能不解决/绕过活动任务升级门禁，也不修改旧固定快照。

## 原子发布、并发与恢复

先检查两个根和两份现有策略；已知策略错误在首个策略写入前阻断。不扫描业务源码猜权限。需要写入的根按固定顺序持有不删除的初始化 flock，锁文件拒绝符号/多重硬链接；锁内再次检查两份策略。策略先在同目录完整写入并 fsync，再用不覆盖的硬链接发布，移除临时名字后重新验证。并发存在的策略只读取校验，不替换。

这是**逐文件原子发布，不是跨目录事务**。磁盘满、权限撤回等异常可能留下第一份已成功策略和初始化锁/目录；错误会列出本次创建项。修复原因后使用同一授权重试，已有有效策略不改。发布中断若留下本工具随机暂存名与最终策略同 inode 的链接，显式重试只移除这个暂存链接，再验证；陌生硬链接仍拒绝。发布前崩溃的孤立暂存文件不自动当授权或广泛清理。
