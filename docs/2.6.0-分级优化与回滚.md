# 2.6.0：任务预算、证据与恢复

本版修正规则与执行脚本的差异，不增加默认角色、默认构建或默认报告。任务难度、范围、风险分别记录，`impactLevel` D/T0–4 保持兼容。文件数只是线索，不能凭改动一行认定低风险，也不能凭工程很大认定高难度。

## 从请求到交付

|任务|初始最少读取|执行和模型能力|最少验证/交付|
|---|---|---|---|
|D/T0 文档、无行为注释|短入口、目标段落|单人、经济型能力、低推理|格式/Schema/Diff，一行说明|
|D/T1 局部文案、颜色、已定位可逆 Bug|目标文件/区域、必要直接调用点和已确认身份|单人、经济型或均衡、低推理；不为流程跑分类器/建状态|Diff、资源引用，真实编译风险才便宜定向检查；无默认截图/设备/新测试/报告|
|D/T2 单页功能、导航/状态/持久化|相关项目事实、文件和局部调用链|均衡、低/中推理；声明任务范围/基线|受影响模块构建与相关测试，行为证据不足才运行目标流程|
|D/T3 共享接口、跨模块、迁移切片|契约、相关模块、紧凑依赖/证据索引|强能力、中推理；先拆片后集成|局部检查、接口兼容、关键集成及失败恢复|
|D/T4 支付/认证/数据/安全/签名/发布|仅当前能力事实、边界和所需证据|强能力，复杂关键判断高推理|支付/账号/数据各自的失败、恢复、幂等；真正发布另核对 Release/最终产物/签名/Profile/环境/适用真机|

模型由当前运行环境明确支持的列表选择；项目模板不预填名称。建议不是已应用，不支持切换就继续当前配置。不得调用付费 API 探测模型。并行需要用户/适用规则允许、至少两个独立且不重叠切片，并且关键路径收益超过协调成本；默认单人，不按等级机械开多角色。

范围不明先定向调查。发现公共状态、权限/支付/数据、跨模块或真实失败再升级；证明仅局部且无该风险可以降级，并记一句依据。相同失败两次无进展停止盲目重试。身份、用户修改、范围、权限、证据冲突时暂停对应动作；独立工作继续。恢复重新核对文件和检查点，不重新 init 覆盖旧基线。

新迁移仍执行完整 Phase 0 与绑定计划批准。已有批准切片和过渡期普通维护不默认重做全项目发现；源/计划变化仍使相关批准失效。旧业务项目不会自动升级。

## 新命令与证据契约

共享 router、迁移 classifier、迁移状态转换和 Gate 均支持 `--dry-run`。router 只输出任务/风险/检查计划，不写上下文或基线；Gate 输出命令、确认状态、用途和缓存条件，不执行命令。状态转换 dry-run 完整检查前置条件，但不创建锁或改状态。

`run_gates.py --profile T4 --purpose targeted` 表示高风险能力定向检查；不能用该报告推进发布。旧 T4 配置默认 `release`，防止旧行为静默放宽。真正发布需要成功的、明确 `buildMode: release` 且命令包含 `buildMode=release` 的 Gate，以及 `release-manual-evidence`：

```json
{"status":"passed","binding":{"当前任务绑定":"由工具取得"},"reviewer":"实际审核者","finishedAt":"带时区ISO时间","release":{"buildMode":"release","bundleId":"确认包名","version":"确认版本","environment":"确认环境","signatureMetadata":{"来源":"最终产物工具输出"},"profileMetadata":{"来源":"最终产物工具输出"},"artifact":{"path":"项目内最终包路径","sha256":"内容摘要"},"deviceEvidence":[{"path":"实际设备证据路径","sha256":"摘要","artifactSha256":"最终包摘要","binding":{"当前任务绑定":"由工具取得"}}],"regressionEvidence":[{"path":"相关回归证据路径","sha256":"摘要","artifactSha256":"最终包摘要","binding":{"当前任务绑定":"由工具取得"}}]}}
```

工具检查合同、内容哈希和当前绑定，不自动认证人工签名元数据或真实业务结论。最终产物签名核验、设备执行和人审必须来自真实操作，不能把合成夹具当业务通过。证书私钥、密码和真实会话不进入证据或基线。缺证据保持未验证。

UI 清单旧 `sourceEvidence: ["path"]` 仍可读，完整验收会 blocked，不伪造升级。新清单使用 `schemaVersion: "2.0"`、当前 `binding`、独立 `coverageSha256`、页面/状态和人工 `review`。预期覆盖为 `{"taskId":"任务ID","screens":[{"sliceId":"切片","screenId":"页面","states":[{"id":"default","interactionRequired":false,"allowNotApplicable":false}]}]}`，其稳定摘要由已批准计划的 `uiCoverageSha256` 绑定。

每条 UI 证据包含项目相对 `path`、`sha256`、`side`、`mediaType`、`capturedAt`、`origin: runtime-capture`、`captureCommand`、`artifactSha256`、`device`、`stateId` 和相同当前绑定。支持 PNG/JPEG、MP4、有节点的 UI 树 JSON、有步骤且 passed 的交互测试 JSON；需要过程的状态不能用静态图代替。评分引用已验证的内容哈希，不再接受任意存在路径。脚本不能认证画面含义；分数明确为人工判断记录。

```bash
python3 frameworks/ios-to-harmony-migrator-v2/scripts/ui_state_manifest.py check /项目/.migration-workspace-v2/ir/ui.json --project /项目 --task-id ID --profile T3 --slice SLICE --expected /项目/.migration-workspace-v2/ir/ui-expected.json
python3 frameworks/ios-to-harmony-migrator-v2/scripts/migration_state.py transition /项目/.migration-workspace-v2 slice_reopened --slice SLICE --task-id NEW_ID --reason 实际矛盾反馈 --dry-run
```

切片重开保留历史并作废受影响切片/发布证据，不重置无关切片。新任务要重新验证，旧 passed 不能关闭新任务。

## 可复现验证与成本

```bash
python3 evals/scripts/safety_regression.py
python3 evals/scripts/run_eval.py fixture-check --output /临时目录/fixture-check.json
python3 evals/scripts/policy_benchmark.py --suite /冻结的套件目录 --cases evals/cases/policy-routing.json --output /临时目录/policy.json
python3 evals/scripts/run_eval.py run --case ios-quick-d1-nil-guard --framework-version 2.6.0 --dry-run
```

只有显式真实 `run`/`run-suite --execute-all` 才调用模型。`fixture-check` 真实安装合成夹具控制文件，绝不执行 App 构建/设备或模型。policy benchmark 只衡量确定性分类，不能证明真实工作流节省。

实际 runner 拒绝伪版本标签，记录套件摘要、固定用例/输入、模型/推理、CLI 和环境合同；比较器拒绝缺失/不同合同。旧结果可查看，不可冒充可复现基线。Token 仅采用实际 usage；无 usage 明确 available=false。读取字节、调用次数、时间不是 Token。模型质量/真实业务效果需另行授权并在选定项目验收。

没有引入持久哈希缓存。本版只复用同一次 binding 内刚校验的规则结果；下一 binding（包括外部命令之后）重新读取。Gate 缓存仅限显式声明 cacheScope=project-only-deterministic 的项目内确定性检查，核对完整代码/命令/配置及 Python 实际解释器摘要；外部 SDK 构建环境依赖未证明完整，默认不复用，T4/发布一律不复用。未经可靠失效机制验证，不采用 mtime 或文件列表推测未变。

## 固定版本、升级与回滚

`installers/install-this-mac.sh --dry-run` 只审查；显式安装时先建立内容固定快照，再注册三个链接，不直接链接可变源码。本版实施不自动运行全局安装、改其他电脑或批量升级项目。

`pin_release.py --destination /指定目录` 默认只预览，`--apply` 生成版本/内容目录，已有内容只校验不覆盖。项目级试用也使用独立固定副本和 manifest，不改用户 PROJECT、lifecycle、业务/签名或历史测试状态。

`transactional_files.py --plan PLAN --transaction BACKUP` 默认预览；加 `--apply` 才应用明确文件清单。先核对所有 before/after 摘要，备份前像后原子写入。`--restore --transaction BACKUP --dry-run` 审查回滚；去掉 dry-run 才恢复。事务后有用户修改时拒绝覆盖。中断记录可恢复，不对未声明路径执行清理。本目录不是 Git，不冒称已有提交或以提交替代备份。
