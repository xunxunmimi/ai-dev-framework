# 2.6.7-task-handoff-review

基于 main `5b6e9d5e352fbbc80e06f3dd6555b8394ed1cd81` 的隔离候选。上传不等于合并、release或安装，不修改任何现有项目。内容以确切commit/tree识别。

## 精确确认 UI 状态

只接受规范相对路径的单个 `*.xcworkspace/xcuserdata/<user>.xcuserdatad/UserInterfaceState.xcuserstate`，包含外层workspace和既有project.xcworkspace。不是对目录、任意用户文件或所有untracked的忽略规则。逐级拒绝链接，遵守原读取/保护边界，不删除或改写UI文件。

首轮旧摘要必须是不可变baseline.json中的实际值；原基线没有此文件时可明确传 `absent`，新摘要仍必须是当前文件的完整SHA256。删除不能被确认。续轮旧摘要必须是上一轮新摘要，`baselineSha256`始终锚原基线；metadataAcknowledgements保存每轮原记录，最新map只表达当前精确值。再次改写、恢复原字节或删除都会重新阻塞，需新预览明确确认，不能覆盖旧审计或称永久豁免。

```bash
python3 "$SUITE/shared/task-routing/task_runtime.py" ack-metadata \
  --project "$ROOT" --task-id "$TASK" --file "$UI" \
  --old-sha256 "$OLD" --new-sha256 "$NEW" \
  --reason "$REASON" --confirmed-by "$REVIEWER" --authorization-source "$AUTH"
# 审查精确路径/摘要/授权来源，再用完全相同参数加 --apply --preview-sha256 <输出摘要>
```

PBX与UI同时已经变化时，两条旧入口可能互相阻塞。使用同一次组合确认，不需把源码/UI回写旧值：

```bash
python3 "$SUITE/shared/task-routing/task_runtime.py" migrate-task \
  --project "$ROOT" --task-id "$TASK" --action continue \
  --operation-id "$OP" --file "$PBX" --metadata-file "$UI" \
  --old-sha256 "$OLD" --new-sha256 "$NEW" \
  --reason "$REASON" --confirmed-by "$REVIEWER" --authorization-source "$AUTH"
# legacy仍须明确 --offline-writers-stopped <来源>；不可绕过规则或读取范围漂移。
# 核 changedContextFiles/metadataAcknowledgement/stateSha256/snapshotSha256/writes，
# 原参数加 --apply --preview-sha256 <输出摘要>。任一文件/状态/revision漂移均拒绝。
```

配置文件列表必须精确等于全部实际身份配置变化。目标/根/仓库改变、不完整任务、保护范围或其他未授权源码漂移继续拒绝。合法独立任务的不同编辑范围仍由所有权检查管理，不能借metadata确认接管另一任务占用的同一路径。执行租约和验证锁未退出时不确认；锁和人工停写来源不构成操作系统沙箱。

原identity/baseline和报告不变。组合确认只更新该任务acceptedContext，不重写全局identity；开始新任务时仍须单独只读核对实际身份，再按明确授权运行identity --write。该动作不释放其他任务，不给新任务旧passed。

## 代码完成而验收未完成

代码交付使用既有closed终态，不新增“等待就自动失去所有权”的状态。先审查最终diff、保存checkpoint，明确开发及验证写入已经结束，再调用：

```bash
python3 "$SUITE/shared/task-routing/task_runtime.py" complete-code \
  --project "$ROOT" --task-id "$TASK" --operation-id "$OP" \
  --reason "$REASON" --confirmed-by "$REVIEWER" --authorization-source "$AUTH"
# 核 codeSnapshot / stateSha256 / snapshotSha256 / writes；同参数加 --apply --preview-sha256 <摘要>
```

必须是新协议active任务，当前自有文件与checkpoint相同，身份/范围/规则一致，pendingExecutions为空，且现存verification.lock未被持有。blocked/waiting-permission/legacy不会自动完成。完整codeDelivery及其生命周期操作记录在单个state中原子提交，handoff为可重建视图。重复原operation只读返回原结果，换参数不能重用操作ID。

closed只表示该执行任务结束、写范围释放。realDevice=waiting-user及验收待办保留；编译/测试/设备报告保持历史，不制造新的通过结论。后续验收以真实制品/代码和新的实际证据处理，不把交付当真机验收。旧任务不能checkpoint重开、生成当前通过绑定或继续受控回写。

后续修改必须新ID重新取范围。默认init仍拒绝dirty同文件；若确实需要承接已交付的未提交修改，必须显式核对来源：

```bash
python3 "$SUITE/shared/task-routing/task_runtime.py" init \
  --project "$ROOT" --task-id "$NEW_TASK" --file "$OWNED_FILE" --request "$REQUEST" \
  --from-delivery "$TASK" --confirmed-by "$REVIEWER" --authorization-source "$HANDOFF_AUTH"
```

仅允许完整closed codeDelivery的精确范围子集，来源state/generation/代码摘要、真实根/仓库/目标/context/revision、规则和读取范围均须仍匹配。释放本身不授权继承；缺交付字段、摘要漂移、普通closed记录或扩大范围拒绝。新state记录predecessorDelivery和初始摘要，新验证从not-run开始，原基线不修改。任务专用模式不允许跨任务继承；自身代码交付与终态元数据重放不扩大旧业务授权。

## 格式与回退

任务协议仍为2，普通旧2.0记录保留，不批量改格式。采用新metadata确认的单个任务使用state schema 2.1 / metadataAckProtocol 2，并完整保留历史链；legacy组合确认仍保存完整legacyState。新运行器严格验证2.0/2.1，缺链、断链、未知格式或伪装回2.0失败关闭。

旧运行器、旧受控writer和旧安装器对2.1状态会因未知schema拒绝，closed也不例外。这是必要兼容限制，不得删除history或降schema让旧入口继续。新audit/update解析目标套件运行器SUPPORTED_STATE_SCHEMAS声明，restore解析备份运行器的同一静态声明；没有声明的协议2运行器只视为支持2.0。现场有2.1记录时，不能通过update或restore安装不认识2.1的运行器，即使全部closed且UI已回原字节。实际update在首个受管写入前还会重核状态与计划运行器能力。支持2.1的目标仍受终态、无租约、原事务和无后续漂移门禁。安装restore不是任务数据回滚。

只有codeDelivery而没有新metadata语义的2.0 closed记录仍可被旧版当历史读取；这不代表新2.1 metadata也可降级。不支持在线混用旧已加载进程；未知外部writer和任意daemon后代不能靠锁空闲证明停写。文件fsync+replace+父目录fsync不能宣称任意硬件掉电耐久。

## 单项目应用步骤（本候选不执行）

1. 明确项目根、确认发布commit和全套摘要，获得单项目安装及精确任务处置授权；保留原工作，不运行全局安装，不复制其他项目的任务或绝对路径。冻结开发、旧/新writer、验证及其后代；不能仅凭PID/锁消失认定无人写入。
2. 只读列出任务/格式/租约和现有受管清单。新协议active/blocked/waiting任务仍阻止升级。本修订不增加在线覆盖或自动关闭。若旧入口因PBX/UI同时变化无法继续，旧版cancel可按明确逐任务授权终结执行并保留源码、基线和验收待办；它不是验收通过。如果不批准终结，停在此，另审离线数据迁移，不绕门禁。
3. 在项目外或明确维护目录备份15个受管文件、manifest/lifecycle/identity/read-policy/验证合同及完整tasks；逐项核SHA、权限、属主、ACL、xattrs、flags、存在/缺失和还原可用性。不删除历史材料或伪造state；缺state材料沿既有review-artifacts逐目录显式审查。
4. 从已核commit的公开git archive构造项目内独立完整SUITE，核所有文件摘要和模式。运行该SUITE的project_framework.py audit与update --dry-run；精确核预计写集和当前任务无漂移，再update --offline-writers-stopped <实际停写交接来源>。artifact review参数须成对文件+原始SHA。不得重跑setup/adopt重登记或只覆盖task_runtime.py形成混合版本。
5. 需更新的受管源仅task_runtime.py、metadata-ack.schema.json、task-control.md。两平台沿现有完整15映射；迁移框架更新共有运行器和任务说明。支持安装器仍会重写框架完整受管清单以及framework-installation.json/lifecycle.json（日常共17既有路径），另建事务/必要锁。完整SUITE还需包含新installer回退门禁、VERSION、测试/文档等；不能只复制3个文件。安装器不自动保全原目标ACL/xattrs，必须按已核备份在同窗口补偿并独立核验。
6. 旧state/baseline/report和所有验收记录不自动迁移。升级改变规则摘要，旧活动任务不能假装继续，也不能自动从跨规则的旧交付继承。新任务先核身份与来源diff；若代码dirty且没有同规则完整交付，需明确人工审阅/合法保存提交后的干净范围，或另审数据交接方案，不能通过部分读取、删记录或新建基线掩盖原修改。本候选不替用户执行Git提交/任务处置。
7. 独立核安装摘要、任务/材料原字节与元数据、入口、锁/进程和备份后再恢复产品写入。真实新init/identity若有既往权限拒绝须由授权范围单独处理，不能换名重放。本候选合成测试不证明设备或产品通过。
8. 任一步失败/拒绝/结果不明都停止新动作，先读权威state、manifest和安装事务。无2.1新数据且符合既有门禁时可按原事务restore并补元数据；有2.1且目标不支持时保留现场、以前滚修复或另审完整数据恢复处理，不自动降级或恢复已经完成的旧任务。
