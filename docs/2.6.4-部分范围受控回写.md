# 2.6.4 部分范围受控回写

项目级固定副本可直接调用任务控制；缺少安装清单时规则身份为 `not-installed`，不能声称旧项目规则已被验证。长期项目策略与单次任务策略必须来自真实授权。任务策略使用 partial 和精确 allow，必要时 deny `.test/**`；不要覆盖已有策略、身份或历史基线。旧任务身份和证据与新字段不一致时必须重新核验。

partial 不运行 Git 或外部验证命令，版本和脏文件状态未核验。用户已有改动必须人工审查。仅将明确授权且确认不含秘密的文件导出至无凭据、无 Git 仓库、无外链的隔离副本；隔离报告只绑定该副本。不要复制 `.test`、签名材料或私人状态。构建配置、依赖和命令需单独核验；不执行真实支付或未经授权的网络操作。

用固定套件的 `shared/task-routing/task_runtime.py init --project <原工程> --task-id <ID> --task-read-policy <任务策略> --file <路径> ... --request <需求>` 建立任务；已有活动任务不要重新建基线。身份、策略或权限不明确时停止。

在隔离位置准备计划 JSON：`root` 和 `candidate` 是原工程和独立隔离目录的真实绝对路径；`reviewedBy`、`reviewNote` 如实记录审查；`files` 每项包含精确 `path`、原工程导出时 `beforeSha256`、候选文件 `afterSha256` 和 `mode`。仅包含任务允许修改的普通文件。人工审查记录不是身份认证、授权或 Git 状态证明。

预先在任务目录中安全创建无链接普通目录 `controlled-writes`；疑似链接或访问冲突时停止。首先预览：

```sh
python3 <固定套件>/installers/controlled_task_write.py --project <原工程绝对路径> --task-id <ID> --plan <计划JSON绝对路径> --transaction <原工程绝对路径>/.ai-project/tasks/<ID>/controlled-writes/<唯一事务名>
```

核对预览及 `previewSha256` 后追加 `--apply --preview-sha256 <预览摘要>`。入口在任务锁内重新检查身份、范围、任务所有权、检查点及前后哈希，仅写计划文件。异常尝试事务回滚；遇到用户后续编辑则停止并报告。成功后人工复核差异并用官方任务控制 `checkpoint`，不会把隔离测试算成原工程通过。

中断后可用 `installers/transactional_files.py --transaction <事务目录> --restore --dry-run` 预览恢复，确认无后续编辑后再去掉 `--dry-run`。备份可能含已授权源代码，应按项目权限保管。此机制不提供操作系统级隔离；发生不合作进程并发写入或无法安全恢复时暂停人工处理。
