# 2.6.6-lifecycle-review：隔离生命周期候选

本地候选基于官方 b79462ca4a3176b96d0bf125abd446cb16eeb32a（2.6.5-import-review）。不是上游发布；没有安装到现有业务工程、全局技能或其他项目，也没有推送。

## 身份与证据

任务协议 `2` / state schema `2.0` 将稳定归属和可变上下文分开。稳定归属含规范真实根、根设备/inode、仓库公共目录标识、worktree 根、平台和目标字段值。根符号别名视作同根；同名副本、其他 worktree 或目标不能自动等同。legacy 没有历史 inode，无法证明原路径过去是否被整个替换；必须显式停写确认后逐条迁移。

原 `identity`、`baseline`、`baseline.json`、报告与检查点保持历史原文。`acceptedContext`、`acceptedRevision`、`acceptedConfiguration`、`acknowledgedContext` 和 `generation` 记录明确承接的配置/revision。PBX 正常变化仍先阻塞；用户核对精确文件后显式承接。目标变化必须新任务。不能自动接受所有漂移，不能用配置承接放宽读取策略、吞掉范围外源码或依赖修改。框架升级带来的规则基线变化也不能借配置承接忽略；此类 legacy 任务通常应取消后新建，不伪造原任务继续通过。

验证绑定继续包含实际当前配置身份、revision、源码与规则、读取范围、验证命令合同，另加入稳定身份摘要、上下文摘要和 generation。承接/检查点/终结后旧绑定失效。通过状态降级 stale；partial 的历史覆盖含义保留，以 `evidenceValidity=stale` 标示失效，绝不升级为 passed。终态 resume 只返回历史，不生成当前验证结论。

## 逐条终结与配置承接

`cancel` 是放弃选定任务，不是验收完成。它不核对已改变的 PBX/源码内容，不重写基线或自动丢弃工作文件；真实根/仓库归属仍核对，只有所选任务释放未来写所有权。waiting-permission/blocked 不会自动释放。没有按时间或进程不存在推导授权。

所有操作先 dry-run，明确 `operation-id`、原因、确认人、真实授权来源；文字记录本身不构成权限认证。预览绑定完整原 state 摘要、generation、项目对象、精确变更旧/新摘要与预计写集。apply 在 tasks.lock 内重核；预览后漂移拒绝。一个任务一次原子提交，没有批量“全成功”事务。多个任务逐条前滚；部分完成时读每条 state 里的 lifecycleHistory 继续，不能回滚已经发生的业务动作。

```bash
python3 shared/task-routing/task_runtime.py cancel --project /隔离样本 --task-id task-1 \
  --operation-id cancel-1 --reason 已确认放弃旧任务 --confirmed-by 审查者 \
  --authorization-source 明确授权记录
# 检查输出的 writes/stateSha256/previewSha256，再用完全相同参数加：
# --apply --preview-sha256 <预览摘要>

python3 shared/task-routing/task_runtime.py migrate-task --project /隔离样本 --task-id task-1 \
  --action continue --operation-id context-1 --file App.xcodeproj/project.pbxproj \
  --reason 已核对工程配置演进 --confirmed-by 审查者 --authorization-source 明确授权记录
```

legacy schema 1.0 还必须 `--offline-writers-stopped <停写确认来源>`。未迁移活动旧任务照常参与所有权冲突；不能通过删记录或重建基线跳过。取消后使用同一操作和原预览重放是只读幂等；复用操作 ID 改参数拒绝。state 内保存原 legacyState 和迁移历史。

部分范围接入只核验已授权的控制目录和明确受管写集；未授权的其他框架目录不探测、不因此算“已排除”，安装仍保留 partial 读取限制。任务专用模式使用已有 `--task-only`：取消/终态重放仅自身任务元数据通道，不新增全局 identity 读取，不扩大原文件白名单；终态业务授权不延续到后续任务。

## 并发与恢复

锁取得顺序为 tasks→verification；外部验证期间仅持 verification，退出并释放验证锁后才再次取得 tasks 回写。开始/结束绑定核对状态摘要与 generation。期间取消、检查点或承接后，只记录历史报告，不更新 completion/status。取消不能杀死外部命令；其验证锁仍在时，同文件新 init 会被拒绝，独立文件仍可开始。执行开始先原子记录 `pendingExecutions`，正常同步退出后只清理自己的租约。runner 崩溃或命令超时后租约保留；父进程消失、锁消失都不能证明子进程/后代停写。先取消旧任务，再确认全部写入者已经停止，逐条 `release-execution` dry-run/apply（要求非空 `--offline-writers-stopped` 来源，活动验证锁仍在则拒绝）后才能交出同文件。安装/恢复也拒绝任何遗留执行租约。正常同步完成的命令仍依赖其同步契约；任意自行 daemon 化的工具不在本候选的进程沙箱保证内。

init 在 tasks 锁内重核身份，发布前再次检查配置/revision。受控 writer、路由、临时外部读取、迁移 Gate/状态机共用协议；旧外部一次性许可绑定完整 state，承接后失效。

state.json 是权威，handoff.md 是派生视图。文件使用临时文件 fsync→replace→父目录 fsync；若 replace 后目录 fsync 失败，提交结果不确定，先读 state 并按操作 ID 重放。交接失败返回 stale-rebuild-from-state，不反滚权威状态。目录 fsync 增强耐久性，但合成故障注入不证明硬件掉电耐久、网络文件系统或 ACL/xattr 保真；不能声称无条件掉电安全。

## 安装与迁移计划（只输出，不在业务工程执行）

### 历史材料目录的显式审计

某些旧工作流把路由上下文、人工交接、日志或附件放在 `tasks/<id>`，却没有权威 `state.json`。默认安装仍拒绝缺失状态的目录，不根据文件后缀、时间或进程情况判断其不占用范围。`review-artifacts <project> --directory <精确名称>` 只读生成 `confirmed:false` 草案；操作者必须逐目录核实其非任务所有权用途，再记录真实审查者和授权来源。

审查固定真实根、设备/inode 及直接条目的名字、类型、设备/inode、大小、模式、mtime/ctime 和链接数。只绑定普通子目录自身元数据，不读取附件或深层内容，不证明历史上从未存在任务。`audit/update/restore` 的 `--legacy-artifact-review <文件>` 和 `--legacy-artifact-review-sha256 <文件字节SHA256>` 必须配对；命令行摘要来自该文件原始字节，区别于审计输出中的结构化审查摘要。实际安装在双锁内重读审查文件和现场，漂移拒绝。

审查不能覆盖任何有效、损坏或未知格式的 `state.json`。缺状态但含 baseline、任务策略、验证锁/历史等持久任务标记时仍拒绝；新 state 出现也使旧审查失效。任务专用范围不能使用此入口，项目读取白名单不会扩大。安装清单和首写前的事务记录保存原审查，混合安装恢复从原事务取相同审查再次核验。所有历史材料原位保留，安装不删除、移动、补造状态或取消任务。该兼容修订需要自己的内容指纹与独立复验，不能沿用此前隔离快照的签收。

1. 停止所有旧/新框架 writer、并行 agent、外部验证和相关开发写入，记录授权与停写来源。advisory locks 无法禁止 Xcode、旧 Python 进程或直接编辑；新 schema 无法让旧脚本自觉拒写，禁止在线混用。
2. 备份原安装清单、受管文件及任务状态；只读审计。新 installer 对 suite AST 协议哨兵、manifest 协议、必需受管入口、未知/部分 task 格式失败关闭。旧 task 仍保留；新协议活动任务阻止实际升级，先明确终结。已有安装重跑 setup 会拒绝，不能绕过审计覆盖。
3. dry-run 后明确离线来源再升级：framework-update→tasks 双锁覆盖整个安装事务；新文件在受管映射与实际复制列表中一致。首次 setup 的锁覆盖 shell 全程；迁移框架安装也覆盖共用入口。
4. 逐条 dry-run 旧任务，选 continue 或 cancel。continue 只接受可核对的相同目标配置演进；规则/读取范围漂移或身份无法证明时拒绝继续。已完成的 B1 closed/cancelled 记录只读历史，不重新激活。
5. 配置承接只更新所选任务，不自动更新全局 `identity.json`。需要开始新任务时，先单独只读运行 `identity`，核对真实项目/平台/目标，再按明确授权使用 `identity --write` 刷新项目当前上下文（锁内重核）；该动作不改任何旧任务 identity/baseline，也不释放旧占用。之后新 ID 的 init 仍独立核对文件已有修改和所有权，不能借刷新身份继承旧 passed。
6. 重跑项目本身的独立验证。隔离通过不证明业务项目产品、设备或工程通过。只有进一步批准后才可制定业务应用操作。

安装 restore 只恢复安装事务文件，不是任务数据迁移回滚；已经产生协议2任务时，拒绝恢复到不认识该协议的旧安装。恢复也要求离线来源和双锁，并拒绝覆盖后续漂移。不能直接降级再让旧 writer 读取新任务数据；需单独审查数据导出/归档方案。

## 剩余边界

配置读取、快照和外部工具不在同一操作系统事务内；前后比较能发现漂移，不能禁止任意外部写入。候选不认证人工授权内容，也不认证开发/验证进程已经停止。单记录提交与安装事务日志各自可恢复，不承诺多记录同时原子。首次旧记录无 inode 的历史缺口不能补造，未知/缺失格式需人工审查，不能强制迁移。部署、发布、push 与真实项目迁移均不在本候选执行范围。
