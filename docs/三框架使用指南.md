# 三框架使用指南

## 第一次安装

在每台 Mac 上运行：

```bash
cd "/你的路径/AI开发框架"
./installers/install-this-mac.sh
./installers/doctor.sh
```

Skill 可按任务描述自动选择，也可以显式写 `$ios-daily-development-rules`、`$harmonyos-daily-development-rules` 或 `$ios-to-harmony-migrator-v2`。项目接入后，根 `AGENTS.md` 和 `.ai-project/lifecycle.json` 会让自动路由更稳定。

## 新项目与现有项目

- 新 iOS 项目创建：可以先用 `vibe-playbook-v2` 与 `ai-dev-kit`，进入维护后安装 iOS 日常规则。
- 新迁移项目：直接使用 `installers/setup-project.sh migration`，不要先安装鸿蒙日常规则。
- 新迁移初始化后先完成 `.migration-workspace-v2/ir/discovery-baseline.json` 并通过 Phase 0 门禁；迁移计划必须绑定发现基线和源索引哈希，用户批准前不得开始鸿蒙业务实现。
- 迁移项目进入提测/修 Bug：运行 `harmony-transition`。普通维护由鸿蒙日常规则负责，等价遗留才使用 V2。
- 已完成迁移的鸿蒙项目：运行 `harmony-daily`；保留旧迁移目录作为只读历史证据。

接入后会生成 `.ai-project/framework-installation.json` 和 `.ai-project/detected-capabilities.json`。前者记录版本和受管文件哈希，后者只缓存工程能力候选，不代表允许执行未经确认的构建命令。

## 安全升级现有项目

```bash
./installers/audit-project.sh /绝对路径/项目
./installers/update-project.sh /绝对路径/项目 --dry-run
./installers/update-project.sh /绝对路径/项目
```

升级器只更新框架受管文件，保留 `PROJECT.md` 等项目事实。只要受管文件相对安装时发生本地修改，更新就停止并列出文件，不提供静默覆盖选项。旧项目尚无安装清单时，不要直接覆盖式重装；先运行 `./installers/adopt-project.sh /项目` 建立当前文件基线，再执行 audit、dry-run 和 update。

## 迁移状态、Gate 和 UI 证据

- `.migration-workspace-v2/state/migration-state.json` 是迁移阶段唯一事实源；用 `migration_state.py transition` 推进，禁止直接改 phase。
- `.migration-v2/gate-config.json` 中自动探测的命令默认 `confirmed: false`。检查 product、module、buildMode、签名和真机边界后才能显式确认。
- UI 切片通过 `ui_state_manifest.py` 记录默认、加载、空、错误、返回恢复、深色和大字体等适用状态。90 分评分不能替代缺失的状态证据。
- `migration-transition` 的边界请求由共享 `framework_router.py` 确定性选择一个主框架。

## 节省上下文和 Token

- 小问题直接描述，Codex 自动判断 D0/D1，不要求运行模拟器或生成报告。
- 只有范围不清、D2+、脏工作区或交接任务才生成 `task-context.json`。
- 每个任务只用一个主框架；语言 Skill 与 MCP 只解决窄问题。
- 历史报告、长日志和全量矩阵默认不读，通过索引按需定位。
- 可读性、扩展性和注释使用同一分级预算：D0/D1 只审当前 Diff，D2 读取受影响平台规则，D3 才做模块边界与公共接口审查；不要为小问题额外调用通用代码质量 Skill。

## Eval 与版本升级

日常任务不自动运行 Eval。升级框架时按以下顺序取证：

1. `python3 evals/scripts/self_test.py`：只测数据集、轨迹解析和评分器，零模型调用。
2. 先执行 1 个与本次改动相关的 quick 用例；只有结果正常才考虑跑完整 12 例。
3. 同一用例的旧版和新版必须固定模型、reasoning、Codex CLI 与 Fixture/revision。
4. 正确性、错误分级、无关修改和无效构建由确定性评分器判断。
5. 可读性、结构、注释、扩展性和 UI/交互仅在发布候选上运行 `judge_quality.py` 独立盲审，避免每个小改动双倍模型调用。
6. 用 `compare_results.py` 做配对比较；没有轨迹 usage 时 Token 保持 unavailable，不用字符数冒充。

完整命令见 `evals/README.md`。24 个真实用例不能直接在日常工作目录执行，必须冻结 Git revision 并使用独立 worktree。

LangGraph/长期 Workflow 仍不属于这三个框架。2.4 已提供可供编排器调用的状态、Gate、审批和证据边界；后续 LangGraph 应作为平级的薄编排层，而不是第四套规则或新的事实源。

## 迁移到另一台电脑

运行 `./installers/package-release.sh`，复制 `releases/` 中的 ZIP。解压后执行 `install-this-mac.sh` 和 `doctor.sh`。Eval 定义、脚本和 Fixture 会进入发布包，历史运行产物不会进入。蓝湖 Cookie、证书、签名和 Token 不在包中，必须在新电脑单独配置。

## 2.5：身份、独立任务、中文注释与安全恢复

参见 [共享任务控制](../shared/context-engineering/task-control.md)。先核对项目根/仓库/分支/平台与目标字段；持久任务每任务独立 baseline/context/state/handoff。源码或身份冲突时暂停，恢复核对真实文件，不覆盖旧基线。报告绑定任务、代码、profile、命令与时间；完成维度分开，真机待用户验收，不默认提交或推送。

升级的 `audit`/`--dry-run` 返回逐文件 Diff，实际更新只改受管规则并在 `.ai-project/upgrades/<id>/transaction.json` 留原文与计划。受管配置漂移拒绝覆盖；需要回退时：

```bash
python3 installers/project_framework.py restore /绝对项目 --suite /绝对AI开发框架 --transaction /绝对项目/.ai-project/upgrades/事务ID
```

恢复也拒绝覆盖升级后新增的本地漂移。旧版项目不自动更新；本轮框架优化不代表业务项目已经接入。每个本次新增/改动的自有函数/方法、成员/属性/常量和重要变量/计算补准确中文注释，排除生成代码与第三方；人工审查参数/返回/异常/异步/副作用/单位/状态/兼容边界，不能靠注释行数或静态规则证明语义。

模型建议与实际设置分开：先模型，再推理，再考虑支持的加速；界面/平台不支持时明确未设置。本轮不运行真实 App 或模型 Eval，由用户选择真实项目后做业务验证。

## 读取受限项目

先按共享 read-boundary.md 明确白名单再接入；2.5.1 不再把缺少授权解释为默认全量扫描。身份/任务/报告保留覆盖范围，partial 不能替代完整通过。部分模式不执行外部编译测试或旧迁移链。

## 2.5.2 任务范围隔离

只核查配置的临时范围不应保存在共享项目 read-policy 中长期生效。项目策略与任务策略显式分层，关闭任务不影响其他对话。历史平台拒绝按具体操作保留，不扩成整个项目目录禁读。
