# 微信小程序 Skill 使用方法

## 1. 它能做什么

`wechat-mini-program-builder` 是一个项目级微信小程序开发 skill，用于：

- 从零创建微信小程序项目并完成第一条可运行功能流程。
- 修改已有原生微信小程序页面、组件和业务逻辑。
- 开发现有 Taro 或 uni-app 项目的微信小程序端。
- 实现路由、状态、登录、网络请求、存储、云能力和权限功能。
- 检查隐私、客户端安全、分包、启动性能和包体积问题。
- 使用微信开发者工具、自动化脚本和真机完成验证。
- 准备上传、提审和发布所需的检查清单。

它不会代替产品规划，也不会未经确认自动上传、提审或发布。

Skill 源目录：

```text
<用户目录>/Desktop/MyProject/wechat-mini-program-builder/
```

## 2. 项目级隔离

这个 skill 不安装到全局，只复制到指定微信小程序项目：

```text
微信小程序项目/
├── AGENTS.md
└── .agents/
    ├── skills/
    │   └── wechat-mini-program-builder/
    └── rules/
        └── wechat-mini-program-builder.md
```

因此：

- 只在当前小程序项目中生效。
- 不写入 `~/.codex/skills`、`~/.claude/skills` 等全局目录。
- 不安装全局插件或 hooks。
- 其他普通 App、Web 项目和迁移项目不会读取它。
- 多个小程序项目可以分别安装，互不共享代码、配置和项目规则。

源目录本身只是安装源。必须运行安装脚本，把 skill 复制到具体小程序项目后，Codex 或 Antigravity 才会在该项目中发现它。

## 3. 支持的技术栈

### 原生微信小程序

支持：

- WXML 页面模板。
- WXSS 页面和组件样式。
- JavaScript 或 TypeScript 页面逻辑。
- `app.json`、页面配置、分包配置和项目配置。
- 原生 Page、Component 和 wx API。

新建只面向微信的小程序时，默认推荐使用微信开发者工具的官方原生模板。

### Taro

支持已有 Taro 项目的微信端开发。Skill 会检查 `@tarojs/*` 依赖和项目构建配置，然后修改框架源码，不直接修改生成的微信端输出。

只有明确需要多端发布、团队已经使用 React/Taro，或现有项目本身就是 Taro 时，才推荐选择它。

### uni-app

支持已有 uni-app 项目的微信端开发。Skill 会遵守 `pages.json`、DCloud 配置和项目现有构建方式，不直接修改 `unpackage/` 等生成目录。

只有项目已经使用 DCloud 生态或确实需要多端复用时才推荐选择它。

### 不会自动迁移框架

已有原生、Taro 或 uni-app 项目会保持原技术栈。把一个正常项目从原生迁移到跨平台框架属于单独迁移任务，必须先确认范围和行为等价方案。

## 4. 使用前准备

推荐准备：

- 微信开发者账号及小程序项目权限。
- 微信开发者工具。
- 小程序 AppID；早期本地体验也可以按开发者工具允许的测试方式创建。
- 如果有后端：测试环境地址、接口说明和测试账号。
- 涉及云开发时：明确的测试云环境和环境所有者。
- 涉及定位、相册、相机、麦克风、手机号、支付等能力时：清晰的用户用途和隐私要求。

官方资料：

- [微信小程序开发指南](https://developers.weixin.qq.com/miniprogram/dev/framework/)
- [小程序配置](https://developers.weixin.qq.com/miniprogram/dev/framework/config.html)
- [项目配置文件](https://developers.weixin.qq.com/miniprogram/dev/devtools/projectconfig.html)
- [小程序自动化](https://developers.weixin.qq.com/miniprogram/dev/devtools/auto/)
- [分包加载](https://developers.weixin.qq.com/miniprogram/dev/framework/subpackages.html)
- [用户隐私保护指引](https://developers.weixin.qq.com/miniprogram/dev/framework/user-privacy/)

平台 API、基础库兼容性、包大小限制、隐私要求和审核规则会变化。开发时应以当前微信官方文档及开发者后台提示为准，不要依赖旧教程中的固定数字或授权流程。

## 5. 安装到新原生项目

### 第一步：使用微信开发者工具创建项目

推荐先在微信开发者工具中：

1. 登录开发者账号。
2. 选择创建小程序项目。
3. 填写项目名称和 AppID。
4. 选择独立项目目录。
5. 根据需要选择 JavaScript 或 TypeScript 官方模板。
6. 确认空项目可以正常编译。

不要让 AI 猜测 AppID、AppSecret、组织权限或云环境。

### 第二步：安装项目级 skill

```bash
cd "<用户目录>/Desktop/MyProject/wechat-mini-program-builder"
./setup-project.sh "/你的微信小程序项目绝对路径"
```

示例：

```bash
cd "<用户目录>/Desktop/MyProject/wechat-mini-program-builder"
./setup-project.sh "<用户目录>/Desktop/Projects/TaskMiniProgram"
```

安装成功后应该显示：

```text
WeChat Mini Program Builder is active only in this project.
```

安装器本身只复制本地文件，不需要 Node.js、`npm` 或 `npx`。

## 6. 安装到已有项目

把包含 `project.config.json`、`package.json` 或小程序源码的项目根目录传给安装脚本：

```bash
cd "<用户目录>/Desktop/MyProject/wechat-mini-program-builder"
./setup-project.sh "/已有微信小程序项目绝对路径"
```

脚本不会删除业务代码，也不会覆盖用户自己维护的同名 skill 或规则。已有 `AGENTS.md` 时，只会追加一次微信小程序 skill 的项目入口。

已有项目首次使用时，应让 AI 先检查：

- `project.config.json` 中的小程序源码根目录。
- `project.private.config.json` 是否属于开发者本地设置。
- 实际生效的 `app.json`。
- `package.json`、锁文件和构建脚本。
- 当前是原生、Taro 还是 uni-app。
- 开发者工具导入的是源码目录还是生成目录。
- 现有测试、环境、隐私和发布配置。

## 7. 开始新对话

安装完成后：

1. 把 Codex 或 Antigravity 工作区打开到目标小程序项目。
2. 不要打开 `<用户目录>/Desktop/MyProject/` 多项目集合目录。
3. 新建对话并明确调用 `$wechat-mini-program-builder`。

新功能示例：

```text
使用 $wechat-mini-program-builder，先检查当前项目是原生、Taro 还是 uni-app，然后实现登录后的任务列表。

要求支持加载、空状态、请求失败重试和重复点击保护。不要把 AppSecret 或生产密钥写进客户端。完成后运行项目已有 lint、类型检查、测试和微信端构建，并给出开发者工具与真机验证清单。未经我确认不要上传、提审或发布。
```

从零做一个小程序：

```text
使用 $wechat-mini-program-builder，从当前微信开发者工具生成的原生 TypeScript 空项目开始，做一个家庭购物清单小程序。先完成本地数据版的一条端到端流程：新增商品、勾选完成、删除和重新打开后恢复。先不要加登录、后台、云开发、分享和支付。
```

修复问题：

```text
使用 $wechat-mini-program-builder，诊断这个页面返回后重复请求、列表重复追加的问题。先检查页面生命周期和异步竞态，说明根因；确认修复范围后修改并验证。
```

发布前检查：

```text
使用 $wechat-mini-program-builder，对当前小程序做 release readiness 检查。核对隐私声明、权限触发、登录和服务端鉴权、域名环境、分包、包体积、错误状态和真机验证。只准备上传与提审清单，未经我确认不要执行外部操作。
```

## 8. 项目检查脚本

Skill 内置只读项目检查脚本。安装后可在目标项目根目录运行：

```bash
python3 .agents/skills/wechat-mini-program-builder/scripts/inspect_project.py "$(pwd)"
```

它会识别：

- 原生、Taro、uni-app 或未知项目。
- `project.config.json` 是否存在。
- `miniprogramRoot` 指向的源码或输出目录。
- 实际 `app.json` 路径。
- JavaScript 或 TypeScript。
- npm、pnpm、yarn 或 bun 锁文件。
- 可用的 lint、测试、类型检查和构建脚本。

脚本不会输出 AppID 的具体值，只会说明是否配置；也不会输出 AppSecret、Token 或项目私密设置。

## 9. 标准开发流程

### 第一步：确认可验收结果

在修改代码前先确定：

- 用户最终能完成什么操作。
- 从哪个页面进入，经过哪些页面或组件。
- 数据来自本地、后端还是云开发。
- 加载、空状态、失败、拒绝权限、重试和恢复如何表现。
- 哪些判断必须由服务端完成。
- 自动测试和人工验证如何证明完成。

### 第二步：保持现有项目结构

Skill 会优先遵循已有框架和代码规范：

```text
已有项目模式
→ 微信平台原生能力
→ 项目现有依赖
→ 确有必要时增加小型依赖
```

不会默认加入状态管理库、UI 组件库、网络框架、云开发、分析 SDK 或代码生成器。

### 第三步：按垂直切片实现

每次先完成一条可在开发者工具中实际操作的小闭环，例如：

```text
进入任务页
→ 拉取任务
→ 显示加载/空状态/列表
→ 新增任务
→ 请求失败可以重试
→ 返回页面后状态正确
```

避免先写完全部接口层、全部组件和全部页面，最后才发现核心流程无法运行。

### 第四步：分层验证

推荐顺序：

1. 格式化、lint、类型检查和单元测试。
2. 原生项目或框架的微信端构建。
3. 微信开发者工具编译。
4. 模拟器验证成功、空、失败、拒绝和重试状态。
5. 测试环境接口或云环境集成。
6. 真机预览和调试权限、布局、网络、生命周期和性能。
7. 必要时使用官方小程序自动化能力覆盖关键回归路径。

只有前端构建成功不能证明微信运行时行为正确；模拟器通过也不能完全代替真机验证。

## 10. 原生项目注意事项

- 所有可访问页面必须在实际生效的应用配置中注册。
- Tab 页面和普通页面使用正确的导航方式。
- 不在 URL 参数中传输敏感信息或超大对象。
- WXML 保持声明式，不放复杂业务计算。
- 循环渲染使用稳定 key。
- `data` 只保存需要渲染的状态，避免频繁传输大型对象。
- 处理页面隐藏、卸载、重复进入和较晚返回的异步请求。
- 及时清理计时器、监听器、观察器和订阅。
- 权限拒绝、取消、基础库不支持和真机差异都视为正常分支。
- 验证安全区域、长文本、键盘遮挡、滚动区域、触摸目标和常见屏幕宽度。

不要把普通网页的 HTML/CSS 行为直接当成 WXML/WXSS 的等价行为。

## 11. Taro 和 uni-app 注意事项

- 修改框架源码，不直接修改构建生成的微信端文件。
- 先读取项目锁定的版本、配置和 package scripts。
- 使用项目现有包管理器，不随意更换 npm、pnpm、yarn 或 bun。
- 微信端特有能力通过框架当前官方方式封装或隔离。
- 每次修改后同时验证框架构建和微信开发者工具运行。
- 多端项目不能因为修复微信端而破坏其他已支持端；必要时运行对应回归。

不要根据网上旧教程猜测当前 Taro、uni-app 或微信基础库命令和兼容性。

## 12. 代码注释规则

注释的目标是保存代码本身无法表达的上下文，而不是逐行翻译代码。

应该添加注释的情况：

- 非直观实现或执行顺序背后的原因。
- 微信运行时、基础库、开发者工具、设备或框架限制。
- 页面生命周期、异步竞态、重试、缓存和幂等约束。
- 登录、服务端鉴权、隐私、数据保留等信任边界。
- 兼容性兜底以及未来可以删除它的条件。
- 无法直接从代码看出的业务规则。
- 对外复用的组件、工具函数、云函数或后端接口契约。

不应添加：

- 复述下一行代码的注释。
- 文件头作者、日期、修改历史或“AI 生成”说明。
- 大段分区装饰线和没有实际约束的说明。
- 注释掉但不舍得删除的旧代码。
- AppID、AppSecret、Token、手机号、用户内容、生产地址或事故敏感信息。

错误示例：

```ts
// 设置 loading 为 true
this.setData({ loading: true })
```

有效示例：

```ts
// 忽略旧页面请求的迟到响应，避免覆盖用户刚刷新得到的新数据。
if (requestId !== this.activeRequestId) return
```

### 平台兼容注释

兼容性或 workaround 注释必须说明：

1. 哪个环境或条件受影响。
2. 不保留这段代码会发生什么。
3. 有条件时附官方文档、问题单或测试证据。
4. 满足什么条件后可以删除。

不要凭记忆编造基础库版本。应查询当前官方兼容表，再填写项目真实支持的最低版本。

### 生命周期与异步注释

涉及 `onLoad`、`onShow`、`onHide`、`onUnload`、计时器、监听器、重复导航、重复点击或请求竞态时，如果清理、去重和执行顺序不直观，应说明具体触发场景。

不要只写“防止重复请求”，应说明重复来自页面再次显示、连续点击、自动重试还是旧请求迟到。

### 安全边界注释

云函数和后端的关键入口可以用 JSDoc/TSDoc 说明服务端必须重新验证的内容：

```ts
/**
 * 服务端权威操作：重新校验资源所有权，并从服务端数据计算价格；
 * 不信任小程序上传的 ownerId 和 price。
 */
```

注释不能代替真实的权限检查、参数校验、隐私声明和测试。

### WXML 和 WXSS 注释

只在非直观分组、无障碍意图、平台选择器限制或布局 workaround 处使用。模板和编译产物可能被检查，因此注释中同样禁止写内部敏感信息。

### TODO 和 FIXME

`TODO` 必须是当前范围确实无法完成、以后可以执行的工作，并遵循项目的问题单格式。例如：

```ts
// TODO(PROJ-123): 提升最低基础库版本后删除该兼容分支。
```

禁止留下没有负责人、问题单或触发条件的“以后优化”“临时处理”。`FIXME` 只用于已知但明确暂时保留的正确性或安全缺陷，并且必须在交付说明中列为风险。

最终代码审查时应检查每条新增或修改的注释，确认它仍然必要、准确、不泄密，并和实际行为一致。

## 13. 登录、后端和安全

微信小程序客户端是不可信环境。客户端代码和网络流量可能被检查，因此：

- AppSecret、数据库管理密钥、签名私钥和生产管理 Token 禁止进入客户端和 Git。
- 客户端临时登录结果必须交给可信服务端或合规云函数完成身份交换。
- 价格、会员权益、订单状态、数据所有权和接口权限必须由服务端校验。
- 昵称、头像、手机号或客户端传来的用户 ID 不能作为授权依据。
- 写请求需要考虑重复点击、生命周期重复触发、超时重试和幂等性。
- 本地缓存需要定义过期、账号隔离、退出清理、版本迁移和损坏恢复。
- 日志中不得输出 Token、手机号、用户内容和其他不必要个人信息。

支付结果不能只根据客户端回调认定，必须由服务端完成权威验证和对账。

## 14. 权限与隐私

涉及个人信息或设备能力时，应逐项明确：

- 为什么需要。
- 具体访问或收集什么。
- 在用户执行哪个操作时触发。
- 保存多久、是否共享、如何删除。
- 用户拒绝或取消后如何继续使用。
- 代码行为是否和后台隐私声明一致。

不要在小程序启动时一次请求所有权限。应在功能真正需要时请求，并提供拒绝后的合理路径。

相机、相册、麦克风、位置、联系人、手机号、支付、广告、分析和生物识别等能力都不能作为默认配置。

## 15. 性能和分包

优化前先测量启动、包组成、渲染、网络瀑布、图片、`setData` 数据量和生命周期任务。

需要分包时：

- 启动页和 TabBar 页面放在正确位置。
- 非首屏功能和私有资源按产品路由拆分。
- 避免公共依赖意外把主包重新撑大。
- 检查异步分包、预下载和独立分包是否真的符合用户路径。
- 使用开发者工具的包分析和性能能力验证结果。

包大小和基础库限制应在执行时查看当前微信官方文档，不在项目计划中写死来自旧文章的数字。

## 16. 上传、提审和发布

Skill 可以准备：

- 构建和开发者工具检查结果。
- 隐私和权限核对。
- 服务类目、用户协议和审核所需说明清单。
- 版本号、版本描述和测试路径。
- 真机、登录、网络、错误和性能验证记录。
- 上传和提审前的剩余人工操作。

以下动作必须在执行前得到你的明确授权：

- 上传代码。
- 提交审核。
- 发布或灰度。
- 修改生产域名、云环境或后台配置。
- 开通付费能力或购买云资源。
- 向审核人员、测试人员或用户发送信息。

Skill 不会保证一定通过审核，因为审核结果还取决于服务类目、账号资质、内容、隐私、功能行为和实时平台规则。

## 17. 与 Vibe Playbook v2 配合

如果是从 0 到 1 创建一个新的微信小程序，推荐同一项目安装：

```text
Vibe Playbook v2
负责产品问题、MVP、体验、阶段和发布目标

wechat-mini-program-builder
负责微信小程序平台架构、实现、调试和提审准备
```

安装示例：

```bash
cd "<用户目录>/Desktop/MyProject/vibe-playbook-v2"
```

## 20. 常见问题

### 新项目应该选择原生、Taro 还是 uni-app？

只做微信端时默认原生。已经使用 Taro/uni-app 或明确需要多端时保持对应框架。不要为了未来可能需要的端提前增加跨平台复杂度。

### 安装 skill 需要 Node.js 吗？

不需要。安装器只复制本地文件。但 Taro、uni-app 或依赖 npm 包的具体项目仍需要项目要求的 Node.js 和包管理器。

### 可以直接让 AI 创建完整项目吗？

可以让 AI 准备目录和代码，但账号登录、AppID、组织权限、云环境选择和设备授权建议在微信开发者工具中由你完成。最稳妥的方式是先用官方模板创建可编译空项目，再让 AI 开发功能。

### 会修改 `dist/` 或 `unpackage/` 吗？

正常情况下不会。Taro 和 uni-app 应修改源码，再通过项目构建生成微信端输出。

### 会自动上传和提审吗？

不会。即使具备操作工具，也必须在执行前得到你的明确授权。

### 会不会泄漏 AppSecret？

Skill 明确禁止把 AppSecret 或生产密钥写入客户端或报告。项目检查脚本也不会输出 AppID 的具体值。

### 可以重复运行安装脚本吗？

可以。由工具管理的副本会安全更新，项目入口不会重复追加，用户自定义同名内容不会被强制覆盖。

### 和普通 Web Skill 有什么区别？

微信小程序具有独立运行时、WXML/WXSS、页面生命周期、wx API、基础库兼容、开发者工具、隐私声明、分包和提审流程，不能把它当作普通网页直接开发。
