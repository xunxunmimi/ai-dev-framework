# 验证预算

| 等级 | 默认验证 | 默认不做 |
|---|---|---|
| D0/T0 | 格式、Schema、Diff | 构建、运行、报告 |
| D1/T1 | Diff；有真实编译风险才做便宜定向检查 | 模拟器、UI 自动化、截图、新测试、独立报告 |
| D2/T2 | 相关构建、测试；行为证据不足时运行目标流程 | 全量回归 |
| D3/T3 | 受影响模块、契约、关键集成路径 | 无关模块与全量设备矩阵 |
| D4/T4 | 按当前支付/账号/数据/安全能力验证失败与恢复；签名/真正发布才要求相关 Release/最终包/适用真机证据 | 因高风险定向修复机械跑全 App 发布；用 Mock 冒充真实能力证据 |

用户明确要求的验证优先。任何通过结果只证明实际覆盖范围。

难度、范围、风险独立判断。`verificationRequirements` 明确列出能力检查、是否要求 Release 和真机边界；T4 targeted 报告不能推进发布。缺失环境/设备只阻塞相应结论，不能伪造 passed。
