# 上下文工程策略

目标是在不牺牲正确性的前提下，只加载当前决策需要的信息。

## 四层上下文

1. **L0 稳定规则**：根 `AGENTS.md` 的短入口和当前主框架核心契约。
2. **L1 项目事实**：`.ai-project/lifecycle.json`、平台 `PROJECT.md`、迁移 `project.json`。
3. **L2 当前任务**：`.ai-project/tasks/<task-id>/context.json`，包含 `mustRead`、`readIfNeeded`、任务文件和验证计划。
4. **L3 历史证据**：报告、日志、截图、矩阵和检查点。默认不读，只通过索引和摘要按需定位。

## 使用规则

- 明确的 D0/D1/T0/T1 可以在内存中分级，不为流程本身运行分类器或生成报告。
- 范围不清、D2/T2 以上、已有大量脏改动或交接任务时，写入任务基线并生成 `task-context.json`。
- 初始分级只基于请求；检查直接调用链后允许升级或降级；最终以实际 Diff 再确认一次。
- 旧脏改动写入 `excludedPreexistingChanges`，不得用于抬高当前任务等级。
- 原始日志保留在原位置，任务上下文只记录路径和结论；不复制长日志。
- 只在阶段边界、D3/T3 切片、同一失败两次或交接时写检查点。
- D0/D1/T0/T1 不写过程记忆；只有已验证、以后仍有用的稳定事实进入项目事实文件。

需要脚本分级时，任务开始运行：

```bash
python3 .codex-rules/_shared/task_router.py \
  --project . --request "当前任务" --platform ios --stage pre \
  --task-id <已初始化任务ID>
```

实现后用 `--stage post`，最终 Diff 用 `--stage final`；用一个或多个 `--file 相对路径` 明确本任务文件。HarmonyOS 把 `--platform ios` 改为 `harmonyos`。清晰的小任务不需要运行这些命令。

## 身份、交接和恢复

改源码前核对绝对根、仓库与分支、平台和目标字段；缺项不猜，不适用明确标记。D0/D1 可只读 `task_runtime.py identity` 并在内存确认，不强制持久任务；D2+、脏目录、并行或交接先按 [task-control.md](task-control.md) 初始化独立任务。恢复必须核对真实文件，不能重新 init 覆盖旧基线。预算是初始文件数/字节软预算，不是实测 Token；必要调用链允许说明原因后按需追加，避免一次加载全部历史。

先选模型与推理等级，再考虑平台明确支持的加速设置。普通任务优先当前合适模型与较低推理；复杂/高风险才升级。Skill 只能建议；平台不支持切换/加速时明确“未设置，继续当前配置”，不得声称已切换或提速；不改账户、凭据或系统安全配置。
