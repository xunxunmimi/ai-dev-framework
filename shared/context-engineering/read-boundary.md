# 项目授权、任务范围和验证覆盖（2.5.2）

长期项目访问、单次任务读取子集、平台拒绝的具体操作必须分开。一次“只核对配置”不能变成所有后续对话的业务禁读；一次平台错误不能推导为整个 Sources/UI/Tests 被禁止。

## 长期项目范围

`.ai-project/read-policy.json` 只保存有来源的长期项目授权，使用 `scopeKind: project`。用户正常授权整个项目访问时可用 `mode: complete, allow: ["**"], deny: []`；这不解除平台实际限制、凭据防护、第三方禁改或验证命令确认。

项目确有明确的长期路径限制时才写项目 deny/partial。不能将本轮未检查、未获准操作或助手自行推断的路径写成永久平台禁读。confirmed 是授权来源记录，不是工具可自行创造的权限。

```json
{"schemaVersion":"1.0","confirmed":true,"scopeKind":"project","projectRoot":"/已确认项目根","mode":"complete","allow":["**"],"deny":[],"scopeDescription":"按用户已有项目访问授权；不代表协议操作或验证命令获批"}
```

可通过 identityFiles 指定稳定工程配置，使身份核对只读配置而不先摘要业务树。identityGitMode: unverified 明确不认证仓库/分支，不能伪装为已经验证。

## 临时任务范围

一次控制接入或只读审查范围放在 `.ai-project/tasks/<task-id>/read-policy.json`。传给 `init --task-read-policy`，不传给项目安装器。

```json
{"schemaVersion":"1.0","confirmed":true,"scopeKind":"task","taskId":"当前唯一ID","projectRoot":"/已确认项目根","mode":"partial","allow":["已允许配置文件","AGENTS.md",".codex-rules/**",".ai-project/**"],"deny":[],"scopeDescription":"仅本次控制层工作，不改变其他对话的项目授权"}
```

有效范围是两层 allow 交集、deny 并集。任务只能收窄项目真实限制。仅按显式任务 ID 装载，线程/调用结束恢复上下文；不寻找“最近任务”，新对话不继承已关闭任务的白名单。恢复旧任务重新装载其范围；丢失、改变或以内存参数替换策略均阻塞，不回退到项目全范围。

旧版无 scopeKind 策略按 legacy-project 保留，不静默放宽。安装器拒绝将新传入的任务范围变成共享项目策略。修正旧版误写时先审计和备份，只改有证据的误扩张，保留用户自定义约束及历史部分报告。

## 平台拒绝的具体操作

`.ai-project/operation-holds.json` 单独记录暂停操作、原错误来源以及已知/未知信息。没有路径级证据时 pathRestrictions 为空，不编造目录黑名单。用户允许访问项目不等于平台批准重试历史被拒操作；原错误未列路径，也不能成为改名、换 operationId 或借其他工具重试的理由。

外部验证的精确命令仍需确认。有暂停记录时，命令必须明确 operationId 并核对与历史操作的关系；同一暂停 ID 或用途不明确时，执行前阻塞。operationId 是用途标注，不是授权 token；原触发命令未知时不假装自动分类可靠，平台实际审批独立生效。普通读代码不等于重跑历史协议验证。

## 读取防护与报告

无策略不扫描；未知/deny 路径在 stat/打开前拒绝。仅支持精确文件、目录/** 或显式 **；拒绝父级跳转、绝对条目、含糊 glob、规范化冲突及跨根。逐层 openat/O_NOFOLLOW 拒绝祖先和叶子链接（含内部链接）及检查后替换；设备、FIFO、硬链接、权限/编码错误、必要配置缺失均阻塞。私密目录和凭据名防护不会因 allow ** 消失。这不是操作系统沙箱。

- passed：本报告定义内的完整范围通过，仍列出生成缓存、任务状态、Git 元数据及凭据等标准排除。
- partial：当前项目/任务子集检查，记录两层摘要及未检查部分，不能升级为全项目通过。
- blocked：来源、范围、策略、链接或证据有问题，不沿用旧成功结果。

部分有效范围仅支持 D0 进程内 verify-config（退出码 3），默认完整证据入口拒绝 partial。外部编译/测试不能由本读取器限制，因此有效范围为 partial 时不运行。任务关闭不把部分证据改为 passed，也不把缺少证据当通过。

## 2.6.1 临时外部只读许可

通过 `issue_external_permit(project, task_id, grant)` 和同一 Python 进程内的 `read_external_once(project, task_id, token, relative)`，只读取一份精确文件。grant 格式见受管 `schemas/temporary-external-grant.schema.json`。需真实用户明确授权来源、唯一授权 ID、任务与项目根、外部根设备号/inode、精确相对文件的设备号/inode/大小/mtime/ctime 和带时区的有效期（最多 24 小时）。使用前核对活动任务状态及项目/任务读取策略摘要；不读取私密路径，不跟随链接/硬链接，不允许文件大于 1 MiB，不执行外部目标文件或外部验证命令。完整项目范围的身份核对沿用现有只读 Git 查询；部分范围不调用 Git，无法确认身份时阻塞。外部根不能与项目重叠或为项目祖先，防止绕过项目 deny。

许可句柄只存在当前进程；用一次、撤销、进程结束、过期、状态/策略变化或发生错误即不能继续使用。同一授权 ID 的摘要审计记录保存在对应任务目录，用于跨进程防重放；记录不包含许可或文件内容，不能拿它恢复许可。`authorizationSource` 是调用方对真实授权的记录，不是平台审批或身份认证；不得由模型自行虚构。平台拒绝仍然独立生效，不能靠新 ID、路径改名或另一进程绕过。

文件名及目录过滤只能保守阻挡常见凭据，不能证明任意内容没有秘密。对目标文件的元数据核对应在用户明确允许读取该文件之后、签发许可之前执行；不因用户授权推断平台许可。

保守边界：项目存在任何尚未解除的操作 hold 时，外部读取许可暂停；本工具不会仅凭不同 operationId 判定与历史拒绝无关。等待有依据地处理暂停后再执行，不影响已授权的普通项目读取。

若任务读取策略为 partial，必须已明确允许读取本任务 state、项目身份、operation-holds 和该任务的授权审计目录；缺项时阻塞，不自动扩大授权。外部内容只在授权进程内返回给调用方，不产生业务文件或缓存；授权审计只含摘要。每次读取前后核对身份与暂停状态，任何不确定或平台拒绝均不能按更换 ID 方式重试。

## 2.6.2 凭据排除与验证范围

统一按名称保守排除常见凭据（例如 `.test/credentials.local.json`、`.env.*`）并拒绝链接；快照不打开、摘要或收录它们。完整范围中的排除项依旧未检查，不保证发现任意名称的秘密；可用项目 deny 缩小范围。升级后旧读取覆盖和证据必须重新核验。外部构建或测试命令不受此读取边界沙箱限制，也不会绑定被排除的输入；需禁止访问凭据时，必须使用确认无凭据的隔离环境，不能推断项目真实构建可安全运行。

## 2.6.3 本机配置

任何路径分量大小写折叠后以 `.local` 结尾或包含 `.local.` 的文件、目录在查询类型、进入、打开和摘要前排除；例如 `sample_app_account.local.json` 和 `sample_app_account.dev.local.json`。该规则也可能排除同名非敏感文件，应核对报告；不同命名的敏感内容不能自动识别，须提前设置明确 deny。规则变化会使旧覆盖和证据失效；子进程不受读取边界约束，禁止接触真实凭据的验证需在无凭据隔离环境运行。
